### 2. Gino Canessa - 2026-08-03

Recommend updating:

Note, it is valid to create two security labels with the same (system+code) but different .display or .version. Furthermore, .display or .version are not taken into account when evaluating security labels.

to

Security labels are evaluated using the system and code elements only - .display and .version are not taken into account. This is a deliberate departure from the way coded elements are normally handled for two reasons:

A CodeSystem used for security labels is required to keep the meaning of each code stable across its versions. Later versions may add codes, including more specific ones, but must not redefine or re-scope the meaning of an existing code. Because the meaning of a code cannot become version-specific, systems processing security labels are not required to be version-aware, and .version has no effect on evaluation.
.display is a human-readable rendering supplied by whichever system populated the label. It carries no processing semantics, and a difference in display never changes the established meaning of a label.

Consequently, it is valid for a resource to carry two security labels with the same (system+code) but a different .display or .version - this commonly arises when content is aggregated from multiple sources.

Such labels are not in conflict, are not an error, and are evaluated as a single label.
