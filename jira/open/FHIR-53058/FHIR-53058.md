- **Description**: Ensure device is capable of recording customizations, such as a brace molded to the patient's body.

Some customizations might be additional devices added to the main device either in an ad-hoc fashion or another as a manufacturer option. I believe this is sufficiently covered already. I think that adjustment of settings (bed to X height) is also likely sufficiently covered.

However, there is a gap around customizations, such as the above brace example, or "cane cut 2" shorter."

We also need to be able to capture custom manufactured devices, such as prosthetics. I see this as somewhat different than "customizations," (modifications of off-the-shelf products) as in this case the entire device is custom built (although possibly incorporating off-the shelf products).

At a minimum, we should be able to track that this device is not interchangeable with other devices (boolean customized?), but I suspect additional details would be useful. However, going all the way down to discrete measurements (ie. Quantities), etc. of the customizations is probably too elaborate. I would think "customization CodeableConcept 0..*" or "customization 0..1 markdown might be sufficient.

We should review the DeviceRequest, DeviceDispense and DeviceUsage to ensure that they can convey this information if appropriate (probably needed on request, less sure on usage and dispense), and review DeviceDefinition to see if any changes are needed.

I would prefer not using an extension for this, as implementers are more free to ignore or strip out extensions than standard elements.

### 4. Michael Faughn - 2025-12-15

DEV WG has discussed.

DEV believes that, with the possible addition of 1 or more extensions, that Device does support the capture of information about customizations. This may involve the use of contained devices (referencing the parent device), use of Device.note, indication of customization via Device.property / Device.property.type.
The scope of possible use cases is quite broad and it would be difficult to craft specific guidelines that served all of these possible use cases. Examples of customizations may range from those that are best expressed through narrative to those that should be captured with element values (e.g., the length a catheter has been cut to). It is expected that implementers would develop profiles that supported their use cases.
One challenge will be to facilitate the convergence on a common profile amongst implementers of a common use case. Perhaps an IG that specifically addresses device customization is in order.
We note that it is important to maintain a proper distinction between configuration and customization.
