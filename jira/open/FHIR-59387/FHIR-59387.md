# FHIR-59387: Clarify where responsible party information is recorded in the DeviceAssociation Resource

## Metadata

- **Summary**: Clarify where responsible party information is recorded in the DeviceAssociation Resource
- **Created**: 2026-09-23
- **Updated**: 2026-09-24
- **Status**: Triaged
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Lisa R. Nelson
- **Resolution**: Unresolved
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: Orders & Observations
- **Related URL**: http://build.fhir.org/deviceassociation.html
- **Related Artifact(s)**: DeviceAssociation
- **Request in-person**: Lisa R. Nelson
- **Description**: It isn't clear which element is intended to point to the responsible party for a device. The Resource is architected to function as a yoking resource, just as PractitionerRole and OrganizationAssociation, but the element names are less clear. Is focus the element that's intended to link to the Organization responsible for the operation of the Device? Structurally it seems it may be, but the narrative doesn't make this clear.

If focus isn't the "other side of the yoke" for tying a Device to its responsible party, then we need to address that gap.

Also that overall description of the Device doesn't mention AI Agents anywhere. That should be listed explicitly in the purpose of the DeviceAssociation Resource.

This purpose description is way to vague. It should have a clearer description of why this Resource exists and what it is intended to do with more examples and the AI Agent situation needs to be addressed explicitly.

This is not enough. "A record of association or dissociation of a device with a subject (e.g. patient) and/or operator."

Adding specific examples which include AI Agents would also be wise to make it easy for implementers to find and understand the purpose of this resource.

## Comments

### 1. Lisa R. Nelson - 2026-09-23

We also need to look at the semantics available in the example value set: https://build.fhir.org/valueset-deviceassociation-relationship.html The example value set should include concepts needed to express the ownership notion supported by FHIR R4 and the notion of "is Responsible Party" for the Device's operation.
