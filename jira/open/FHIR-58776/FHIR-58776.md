- **Description**: `TestScript.setup.action.operation.accept` and `operation.requestHeader` can both be used to set the HTTP `Accept` header.

The main difference appears to be that `accept` may contain shorthand values such as `json` and `xml`, which the test engine converts to FHIR media types, while `requestHeader` sets the supplied value as-is.

Having two ways to represent the same HTTP header makes TestScripts less lean and introduces ambiguity. For example, I cannot find defined behavior for an operation that contains both `accept` and an `Accept` request header.

A leaner and less ambiguous TestScript structure would have one authoritative way to set request headers. `requestHeader` already supports regular FHIR media types, other media types and values used for negative testing.

Could `operation.accept` be deprecated in favor of `requestHeader`? If the shorthand conversion provided by `accept` is intentionally retained, could it be treated as a specifically scoped convenience and could the interaction with `requestHeader` be defined?
