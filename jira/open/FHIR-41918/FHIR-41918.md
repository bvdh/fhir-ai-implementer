- **Resolution Description**: There is no expectation that the presence of a targetProfile means the reference must resolve.

Will add the following comment to ElementDefinition.targetProfile:

"The presence of one or more targetProfiles for a Reference or canonical does not mean that the Reference or canonical will contain enough information to allow resolution. E.g. A Reference might just have .display, or a canonical might have an extension in place of a value. The expectation with the targetProfile is that if the element does resolve to a resource, that resource SHALL comply with at least one of the listed targetProfile options."
- **Resolution Vote**: Rick Geimer/Emma Jones: 8-0-0
- **Vote Date**: 2023-12-18
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: If a reference is constrained to specific resource types, it's valid to include a .display or .identifier without having to populate .reference pointing to a valid referenced resource. But it is argued ([here|https://chat.fhir.org/#narrow/stream/179190-united-states/topic/reference.2Eidentifier.20conformance/near/381589986) that

"If a reference is constrained to a specific profile, it SHOULD contain a reference that resolves to a valid instance of that profile. It MAY contain an identifier that identifies a valid instance of that profile, somehow. It MUST contain one of those." (As I understood it.)

Include this guidance, or other guidance if incorrect.
