- **Resolution Description**: The text today is informative, discussion agrees to move to normative, and to address the comments in this ticket. Edit the paragraph following as shown:

Bundle: A bundle is a container for a collection of data. Some uses of Bundle are communicating search results, sending data, or persisting data (see Bundle). The Bundle.meta.security would SHALL carry metadata about the data contained in the bundle and security conditions for the bundle. Specifically the confidentialityCode 'high-watermark', the authorized purposeOfUse, the required compartment clearance, Refrain, and Obligations that must be maintained, where the "high watermark" is an indication of the highest confidentiality level. Depending on Policy, the Bundle mightMAY include the cross-section of sensitivity or integrity, although this is usually not included. Provided in the Security Label Event Examples value set contains security-label codes that would be used on Bundle.meta.security. The Bundle creator SHALL apply the `Bundle.meta.security`, the Bundle consumer response is an implementation detail.

- **Description**: The guidance section prescribes using bundle.meta.security for high watermark. Further clarification is needed for the following:

is the server required to 'compute' the high watermark based on the security labels on the individual resources in the bundle or can it use the bundle security label as a short-hand to mass-label all the resources in the bundle?
how should the consumer treat a bundle where the bundle security labels is NOT set to the high watermark. For example, there are R resources in the bundle but the bundle is set to N security label.
should the server include high watermark for non-hierarchical security labels other than confidentiality? (for non hierarchical labels, high watermark is defines as the "super set").
