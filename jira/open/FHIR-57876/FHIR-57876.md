- **Description**: Extracorporeal Life Support is an established support modality for critically ill patients. It provides pulmonary and/or cardiac support by guiding blood through an extracorporeal circuit, replacing lung function, adding oxygen, and removing carbon dioxide, before returning the blood back to the patient.

An ECLS circuit typically consists of multiple components: tubing, a blood pump, cannulas, a gas exchanger (oxygenator), a console for setting circuit parameters, and a heat exchanger.

The circuit setup varies depending on the support mode and clinical course. Therefore, in some cases, a temporal relationship between components and the circuit, as an abstract device that holds everything together, must be established. In other cases, components can be reused for a second circuit if the circuit was replaced. Right now, one can solve this issue using multiple DeviceAssociation resource instances. This is clunky, especially when many devices need to be interconnected, or components change a lot during a run (think of run as the episode of exposure to ECLS).

The Device resource provides an attribute that could provide a clearer solution. Device.parent. Unfortunately, it comes with two major constraints.

The cardinality won't allow multiple parents
The temporal relationship between the device and its parent is not mappable

Adding a multiplicity for Device.parent and a time period per entry would solve this issue. Further, Device.parent implies an "upward" linkage. It would be nice to also have a top-down view. To be agnostic about a parent or child relationship, I would further propose renaming Device.parent to something like Device.relatedDevice. A categorical qualifier such as {parent|child} or {is-part-of|contains} could help future Implementation Guides denote the relationship, allowing for greater flexibility.

Thank you for openly discussing this topic and let me know if I can be of any assistance!

Clemens Rieder, M.D.

Addendum: It might be worth considering enabling device topology as well. ECLS circuits come in different configurations. Based on the components present, these could be arranged differently. Having some sort of linkage, like Device.upstreamDevice and Device.downstreamDevice, could make it easier to build actual graphical representations of these circuits.
