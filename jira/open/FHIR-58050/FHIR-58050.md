- **Description**: There is some ambiguous information about the usage of $validate-code on CodeSystem.
The guideline states that:
"...If the operation is not called at the instance level, one of the parameters "url" or "codeSystem" must be provided. .... When invoking this operation, a client SHALL provide one (and only one) of the parameters (code+system, coding, or codeableConcept). Other parameters (including version and display) are optional. ..."

According to the second sentence a client has to provide for example code+system. However, the first sentence indicates that the system part is not necessary when the operation is called on an instance level. Which is clear because in case of URL: [base]/CodeSystem/[id]/$validate-code, the CodeSystem is already uniquely identified by its ID.

This seems like a copy&paste situation from the ValueSet/$validate-code operation, where the system input parameter is used to identify a specific CodeSystem within the ValueSet.

The proposal is to distinguish in the description if this operation is called on an instance level or not and which input parameters to use in those cases to make it unambiguous.

Furthermore, about the „code+system" part in the second sentence:

Since there is no is no "system" input parameter, better use the actual parameters "url" or "codeSystem" for that example

### 2. Carmela A. Couderc - 2026-09-16

See proposed resolution in FHIR-56399 - TI is reviewing all input and output parameter definitions for consistency and clarity. As of today, $validate-code on CodeSystem is drafted to

add a new parameter, canonical: state: Identifies the code system to use for validation as an optionally-versioned canonical reference. It is an error to use this parameter when the operation is invoked on an instance or if `url` or `codeSystem` are provided.
Update the url parameter documentation to:

Identifies the code system to be used specified as a canonical reference without a version. The server must know the code system (i.e. it is defined explicitly in the server's code systems, or it is known implicitly by the server). It is an error to use this parameter when the operation is invoked on an instance or if `codeSystem` or `canonical` is provided. Note that for backwards compatibility, canonical references in terminology operation parameters are represented using the `uri` type, rather than the R4 `canonical` type.
