- **Description**: ClaimResponse.payment.adjustmentReason includes preferred reasons for "Prior Payment Reversal" and "Prior Overpayment." The ClaimResponse.payment element should allow linking to the Claim or ClaimResponse from which the overpayment or reversal originated. Think of it like an "Adjustment Source" or something along those lines.

The adjustment and adjustmentReason elements do not give enough flexibility to identify why an adjustment was made or the source for that adjustment. If the adjustment was the result of an overpayment, the spec should allow flexibility for identifying the overpayment itself.

### 2. MatthewMcCandless - 2026-09-15

pknapp In X12, non-claim adjustments are communicated in PLB segments. The PLB segment allows for a reference number that insurances use to communicate which other claim's overpayment is causing the reduction in payment for the current claim.

X12's implementation is challenging for providers because the reference field is free text, with each insurance determining what format to send that information. Also, X12's implementation is a field that exists in relation to the check, not the individual claim adjudication. That makes it difficult in today's world because the data arrives per-check, but the reference number free text is used to associate it with specific claims.

So, what I'm proposing is currently used in an existing standard, just poorly
