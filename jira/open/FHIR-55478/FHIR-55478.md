- **Resolution Description**: Agreed, deprecate the lockedDate element:

Add standards-status extension to the element to deprecate it.
Add a deprecation note to the definition comment stating: This element has been deprecated because there are established methods to lock a valueSet definition to a version (ValueSet.compose.include.version and ValueSet.compose.exclude.version{}) or to declare a version to be used in an operation.
- **Resolution Vote**: Carmela Couderc / John Carter : 7-0-4
- **Vote Date**: 2026-09-22
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: The ValueSet.compose element has a "lockedDate" element. However, there is no mention of this element in any of the rest of the ValueSet and terminology documentation, including expansion details, $expand operation documentation, or any other part of the specification. In addition, the functionality this element is intended to provide is more effectively provided through the use of the various -version parameters available in the $expand operation.

In addition, there is no mention of lockedDate in the TxEcosystem requirements, nor in any of the TxEcosystem tests.

Suggest that this element be deprecated with an indication that the capability is more effectively provided through the use of the -version parameters.
