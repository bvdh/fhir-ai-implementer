- **Resolution Description**: We are changing the element name and scope to include more statuses. We don't want to provide contsraints on which status values require/allow reason (in theory, any status can have a reason).

The element is being changed by FHIR-56428(https://jira.hl7.org/browse/FHIR-56428), which renames `notPerformedReason` to `statusReason` and widens its scope to reasons for status changes; see that ticket for the change. We will not add guidance or an invariant on which statuses require or allow a reason: in principle, any status can have one.
- **Description**: The element notPerformedReason is defined as: "Indicates the reason why a dispense was not performed."

However, the status values that indicate "not performed" are ambiguous:

cancelled - Was it not performed?
unfulfilled - Explicitly not performed (new in R6)
declined - Not performed (patient declined?)
on-hold - Temporarily not performed but might be later

Issues:

When exactly should notPerformedReason be populated? Only for unfulfilled? For cancelled? For declined?

Propose Adding guidance or an invariant on which status values require/allow notPerformedReason.
