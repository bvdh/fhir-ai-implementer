- **Description**: Add a new code called "signed" to the value set for MedicationRequest.status (https://hl7.org/fhir/6.0.0-ballot5/valueset-medicationrequest-status.html).

For inpatient workflows, a MedicationRequest is typically signed by a provider and then verified by a pharmacist. In typical FHIR implementations today, a MedicationRequest is in draft status until it is signed, at which point it becomes active. However, this model does not indicate when an order is signed but not yet verified.

We are proposing a new workflow step in between draft and active called signed. In this model, a MedicationRequest would start in draft status (as it does today), and once signed, it would change to the new signed status. Then, once it has been verified by a pharmacist, it would move to active status.

The new signed status would likely only be used in inpatient workflows. For outpatient workflows, especially when the order is being transmitted to an external pharmacy, the MedicationRequest would likely still move directly from draft status to active status when it is signed.

### 2. Lloyd McKenzie - 2026-10-03

I think this is more of a business status than a functional status. The order itself is either 'draft' (in the process of authorship, but not yet actionable) or 'active' (which means it's actionable). An order may go through a variety of steps before it becomes actionable, but we don't want to try to model all of those. It might be reasonable to add a business status, though it needs to be clear that it's strictly limited to flow through the 'authorization' process and isn't allowed to communicate anything about execution workflow.
