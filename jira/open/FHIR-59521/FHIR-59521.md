- **Resolution Description**: Add Medication.classification 0..* CodeableConcept, after Medication.code:

Short: "Classification of the medication"
Definition: "A classification of the medication, such as a therapeutic, pharmacological or anatomical classification (for example, ATC)."
Comment: "Classification does not replace Medication.code, which identifies the medication. The classification system is identified by the code system of each coding. A medication can have classifications from several systems."
Binding: example binding to http://hl7.org/fhir/ValueSet/medicinal-product-classification (ATC, as an exemplar), the same value set as MedicinalProductDefinition.classification.

Consequential changes:

In the Extensions Pack, mark the medication-classification extension as not to be used with R6 and later, pointing to Medication.classification (it remains for earlier versions).
In the MedicationKnowledge mapping in the Medications module page (FHIR-57378): medicineClassification → Medication.classification.
- **Description**: At the Pharmacy WG meeting of 21 May 2026 at the Rotterdam WGM (mapping of MedicationKnowledge elements to other resources; minutes), the WG agreed for MedicationKnowledge.medicineClassification: "In Europe, classification is often put in the prescription (ATC) — put in Medication".

Medication has no element for classification. FHIR-45874 added the medication-classification extension, which mirrors the type/classification/source structure of MedicationKnowledge.medicineClassification. The type and source parts of that structure are not used in practice: the classification system is identified by the code system of the coding (for example, ATC). This ticket implements the meeting decision with a simple element, consistent with MedicinalProductDefinition.classification. With FHIR-57813, Medication can optionally be a canonical resource and replaces MedicationKnowledge, so classification belongs in the resource itself.
