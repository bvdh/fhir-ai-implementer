- **Change Category**: Enhancement
- **Change Impact**: Non-compatible
- **Applied for Version**: R6
- **Description**: The statusReason element appears to be a string.

Would a CodeableConcept make sense so that implementation guides could define specific values to include?

I see the resolution to https://jira.hl7.org/browse/FHIR-54162 was to change this element to a CodeableConcept, but it still appears to be a string.
