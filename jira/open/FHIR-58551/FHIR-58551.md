- **Description**: `ResearchStudy.descriptionSummary` and `ResearchStudy.description` are separate `markdown` elements with cardinality `0..1`, although they represent different variants of the same general content.

Please consider consolidating them into a repeatable complex element, using `ResearchStudy.label` as a model. It could contain:

a type distinguishing summary and detailed descriptions
the description value as `markdown`
the language of the description

This would support multiple description variants and languages in a consistent structure. If the existing elements are retained, please add guidance on representing multilingual descriptions.

## Comments

### 1. BrianAlper - 2026-10-19

Consider deprecating ResearchStudy.description and ResearchStudy.descriptionSummary (to avoid breaking prior data) and adding ResearchStudy.abstract 0..* BackboneElement containing:

.type 0..* CodeableConcept binding (Preferred) to https://terminology.hl7.org/en/ValueSet-cited-artifact-abstract-type.html

.language 0..1 code

.value 1..1 markdown

Also consider THO change to the value set (to remove 'language') in coordination with EBMonFHIR project.
