- **Resolution Description**: Include the optional additional parameter to filter the results:

minimumScore (0..1) decimal

Description:

Filter the results of the match to include only patients where the Bundle.entry.search.score is greater than, or equal to the provided value.

Note: Care should be taken if handling score values across multiples systems, as the calculation between them could be meaningfully different.

Also include the above note before the examples (at the end of the other general notes that include the score - specifically if the match is across systems)

- **Description**: Would it be possible to add an optional parameter [0..1] for the $match operation on Patient to permit a confidence level to be specified as a value between 0.0 and 1.0? This would translate to functionality offered by MPI Services to reduce the confidence level of the search and therefore permit multiple potentially-matched Patient resources to be returned. The Response includes the confidence level of the match for each returned Patient along with the other fields defined for Patient. Not sure how you go about slipping that additional piece of response data into the searchSet bundle along with each Patient entry.

brian.postlethwaite cooper.thompson Here's documentation about the Verato API for patient matching.
Verato's patient matching API does not support a "Confidence" parameter in the way that other systems might, but it does produce a match score that indicates confidence. Rather than returning a single probability, Verato uses a "Referential Matching" approach that leverages a large, proprietary reference database to achieve high accuracy.
Here is how Verato indicates match confidence and allows for different matching thresholds: * Match Scores: When Verato's API returns a potential match, it includes a match score between 0.0 and 1.0, with 1.0 indicating the highest level of certainty. Verato provides clear documentation on how these scores relate to matching certainty.
