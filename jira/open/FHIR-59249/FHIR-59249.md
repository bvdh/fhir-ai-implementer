- **Description**: Affected elements in the current Testing IG build:

`TestScript.setup.action.assert.key`
`TestScript.setup.action.assert.evaluateBasedOn`

The current Testing IG build introduces `assert.key` and `assert.evaluateBasedOn`. `evaluateBasedOn` is defined as a list of `assert.key` references used to conditionally determine whether an assertion is evaluated. This does not define the actual condition.

For a single reference, it is unclear which result causes the dependent assertion to be evaluated. For multiple references, it is also unclear whether all referenced assertions or at least one referenced assertion must satisfy that condition.

Please define:

which assertion results cause the dependent assertion to be evaluated;
how multiple references are combined;
whether an assertion whose condition is not met receives `skip` or another result.

A possible default is to evaluate the assertion only when all referenced assertions passed, and otherwise mark it as skipped. However, this does not cover all relevant use cases.

A TestScript may need to evaluate additional assertions when a referenced assertion fails, for example to provide information that helps a user investigate the failure. Evaluation may also need to depend on the value evaluated by a referenced assertion rather than only on its outcome.

Please either define how `evaluateBasedOn` can represent these conditions or limit its intended scope explicitly.
