- **Description**: There's no need to specify resource, because notificationShape is already nested inside trigger, which has resource as 1..1
There's no reason for notificationShape to be 0..*. Given that you can only have one root resource and everything else provided is defined by includes and revIncludes, you only need one. All of your examples only have one
The https://build.fhir.org/subscriptiontopic-example-admission-parameters.xml.html shouldn't need a notificationShape, as it's not defining any filters. The shape automatically includes the matching resource (though you'll only get that if you ask for content).
