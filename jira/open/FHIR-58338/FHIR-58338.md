- **Description**: We haven't reviewed what search parameters that EvidenceVariable should have for real world use. We should take the time and discuss that so EvidenceVariable resources are findable on a FHIR server.

Here are some search parameter suggestions I have:

For EvidenceVariable.definition, we could have search parameters for EvidenceVariable.definition.concept.coding.code and EvidenceVariable.definition.reference
So definition-code and definition-reference could be the parameter names.
EvidenceVariable.handling could have a search parameter name handling.
EvidenceVariable.classifier could have a search parameter name classifier.
EvidenceVariable.actual could have actual. Not as important.
EvidenceVariable.category could be a token search parameter named category.
And EvidenceVariable.category.valueReference.reference could be category-reference.
EvidenceVariable.relatesTo.type and EvidenceVariable.relatesTo.target[x] make sense to have search parameters too.
Maybe EvidenceVariable.effectivePeriod?

## Comments

### 1. BrianAlper - 2026-08-17

Of the suggested items, I would suggest adding search parameters for:

EvidenceVariable.definition.concept.coding.code using definition-code
EvidenceVariable.handling could have a search parameter name handling.
EvidenceVariable.classifier could have a search parameter name classifier.
EvidenceVariable.actual could have actual. Not as important.
EvidenceVariable.relatesTo.type – this search parameter could be repeated for any Resource with a relatesTo element
EvidenceVariable.relatesTo.target[x] – this may be complicated by the different datatypes
Maybe EvidenceVariable.effectivePeriod?

And not for:

EvidenceVariable.definition.reference – hard to explain what you are searching for when a Group resource is used as a conceptual cohort definition to provide the definition detail
EvidenceVariable.category — this element is used for categorical variables to name and define each possible value; not clear how common this complicated search parameter would be used
