- **Resolution Description**: Section "6.2.8. Provisions" intends to clarify the model. It clearly states that the model starts with a base/default 'decision' permit/deny and each subsequent provision (or sub-provision) articulates the circumstances that would to an exception to that decision. In other words, we start from the base decision, and we navigate down the tree of provisions, each layer would lead to flipping the decision if there is a match.

While these are clearly expressed in that section and through the example, we will take another pass to improve and further clarify this intention.

As part of the resolution for this ticket we also need to update the description for `Consent.decision` in the 6.2.5.1. Terminology Binding which is using the old description.

Clarify in the text that the decision element affects only the first row of provisions, that is to clarify that it is not a statement of permit vs deny against policyBasis. as policyBasis is not being voted on, it is simply the basis. (e.g. a patient that denies a OPT-IN Consent would not be indicated as that OPT-IN basisPolicy with a decision=#deny.

- **Description**: The current consent model is quite different from the previous consent model in R4. In the new model, theirs is an overall decision "permit/deny". This is quite different from R4 model where the "permit/deny" is on each provision.

This ** change makes me confuse as previous in the provision there're very rich information to define the context of the decision, e.g., time, data, purpose, actor. However, now the context of overall decision is not clear to me. If I put "permit" here, what am I permitting? Is it the policyBasis, policyText, or regularotyBasis? Is there other context information on the data, the treatment, the time? For my understanding, every consent shall have a context, no one will permit anything.

Maybe it is because I'm not understanding correctly. However, would like have better understanding of this new model as well as the rationale behind the change since R4. And suggest some explanation to be included in the description of the resource.
