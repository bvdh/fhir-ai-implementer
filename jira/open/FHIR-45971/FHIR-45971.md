- **Description**: At present, the parent property is fixed to a data type of 'code' which means that it's not obvious how (or even valid?) to represent a concept that has a parent in a different code system.

We should either allow the parent to be a code or a Coding, or define a different property for a foreign parent

well, the case would be if you decide to extend an existing code system with your own concepts to specialise it further. You can't do in the other code system, but you can do it in your own. And I've seen it down several times, including with LOINC and PBS in Australia.

I don't understand how you could define a child in another code system, which is why I didn't raise it.

I think that we could comfortably say, 'we think that his is generally a bad idea' - and we should, in the specification, but I don't think we can say, 'its impossible to do this'
