# FHIR-59519: Allow Medication to be defined by its canonical

- **Resolution Description**: We will allow a Medication that represents a physical instance to reference the Medication that represents its kind, by the kind's canonical URL. We will:

Add the reference to Medication, either by adding Medication as a target of Medication.definition, or by adding a new element, for example Medication.instanceOf 0..1 canonical(Medication), following Device.definition. In the second case, Medication.definition remains for the regulatory product definition resources.
Add guidance: "Used when this Medication represents a physical instance (Medication.instance is present) and the kind is represented by a Medication used as a canonical resource (FHIR-57813). A Medication SHOULD NOT reference itself or another instance Medication as its kind."
Describe the kind–instance relationship in the Medication Scope and Usage.
Link the FHIR-57429 example pair through this reference.

Referencing a versioned canonical (url|version) will be taken up with FHIR-I for confirmation before the mechanism is chosen. The canonical type supports url|version. A Reference may contain a canonical URL, but the |[version] syntax is not supported (see references.html). FHIR-I's answer decides between the two options above. Pharmacy's preference is whichever lets an instance reference a specific version of its kind.
- **Description**: FHIR-57813 (Persuasive, 2026-07-06) makes Medication optionally a canonical resource. A Medication can then represent a kind of medication, which can be published, versioned and referenced by url. A Medication can also represent a physical instance, using Medication.instance (serial number, lot number, expiry date).

There is currently no way for an instance Medication to reference the Medication that represents its kind. Medication.definition only allows Reference(MedicinalProductDefinition | AdministrableProductDefinition | PackagedProductDefinition | ManufacturedItemDefinition). As a result:

an instance can only be linked to its kind by repeating the same code, which is not reliable when the kind is identified by url/version or by a local identifier rather than a code;
systems that keep a catalogue of Medication kinds (for example, a formulary or stock system) cannot link the physical items they hold to the catalogue entry;
the example pair proposed in FHIR-57429 (one Medication for the kind, one for an instance) can only be linked by code.

This is a consequence of FHIR-57813. Now that Medication can represent a kind in its own right, an instance needs to be able to point to it, as it can already point to a MedicinalProductDefinition.
