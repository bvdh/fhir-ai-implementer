- **Resolution Description**: Note: PA notes that this ticket is about a resource in our incubator IG. R6 is currently out for ballot, but our understanding is that tickets for incubator resources can still be addressed.

We will fully remove the VerificationResult.targetLocation element.

We considered whether to deprecated instead, but VR was FMM 0 in R4 and FMM 1 in R5, and no in the incubator IG, so maturity is low, and we know of no implementers, and only the VhDir and NDH IGs profile it (and they are asking for the removal), so we are going with a full removal.

We will add a narrative section to VerificationResult calling out the extensions that can be used to target sub-resource content:

Element Level Verification

The VerificationResult.target MAY point at a specific element within the targeted resource using the target element extension or target path extension. For example when updating a PractitionerRole.location to indicate a practitioner now offers services at a new location, the VerificationResult can indicate that the verification was done specifically on the PractitionerRole.location element.

- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Description**: The VerificationResult.targetLocation element should be deprecated (removed), and as a fhirpath is not sufficient for indexed elements.

There are two extensions available that Provenance (and others) use for targeting elements in a resource. These extensions should be used. See https://build.fhir.org/provenance.html#element

Note: These elements can be used backward compatible with VerificationResult, as extensions on the .target element.
