- **Description**: >The Access Control decision engine uses the security label together with any provenance resources associated with the resource and other metadata (e.g., the resource type, resource contents, etc.) to ... determine what resources can be returned

This is a bit nit-picky – The access control decision engine described here and on the security page are commonly RBAC, or ABAC engines (google suggests additional models are ReBAC, PBAC and ACL). Most of these access control schemes rely primarily upon information (roles, attributes, relationships) that aren't modeled or stored or provided in FHIR.

I think it would be a lot more accurate to change this sentence to something like –

>The Access Control decision engine uses the security label together with any provenance resources associated with the resource and other metadata (e.g. user role or attributes, resource type, resource contents, etc.) to ... determine what resources can be returned
