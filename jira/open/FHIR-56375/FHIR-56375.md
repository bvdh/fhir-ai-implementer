- **Resolution Description**: The problem as stated in the ticket is no longer valid as the .network property was removed from Practitionerrole base specification. FHIR-53853

However, there is an extension that is available to the US-Realm which is the basis of the 'network' concept covered in the documentation. So, an alternative narrative is proposed:

Within the comments of the PractitionerRole.organization attribute
the example for networks will be moved below the last sentence "Each of the examples above above, would be represented as different PractitionerRole instances, each with a different values for PractitionerRole.organization."
and changed from:

A practitioner is part of a payer's network (such as a preferred provider organization (PPO), or health maintenance organizations (HMO)). PractitionerRole.organization would represent the payer's network.

To:
A practitioner is part of a payer's network (such as a preferred provider organization (PPO), or health maintenance organization (HMO)). PractitionerRole.organization should not be used to represent that payer's network. In such a case, an extension should be used.

- **Description**: In the detailed descriptions section (8.5.9), the 'comments' for practitionerRole.organization state:

"Some relationships (represented as PractitionerRoles) that may exist between practitioners and organizations include:

A practitioner is part of a payer's network (such as a preferred provider organization (PPO), or health maintenance organizations (HMO)). PractitionerRole.organization would represent the payer's network."

Given a data element for 'network' was added to the resource, this example is no longer relevant/needed and should be removed.
