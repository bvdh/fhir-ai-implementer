- **Description**: Affected elements:

`TestScript.setup.action.assert.operator`
`AssertionOperatorType`

The `empty` operator is defined as “Compare value is empty.” The specification does not define whether this includes a selector that does not resolve to a target, or only a target that exists but has an empty value.

These cases are not equivalent. For example, a TestScript may need to assert that an HTTP `If-Match` header was not sent. A missing header satisfies that requirement, while a present header with an empty value does not: the header still exists and may be interpreted as malformed input.

Using `headerField` with `operator = empty` cannot express this distinction unambiguously.

Please add a `notExists` operator with the following semantics:

the assertion passes when the selected header, element or value does not exist;
the assertion fails when the target exists, including when its value is empty.

The `empty` operator should apply to a selected target that exists but has an empty value.

The corresponding `exists` operator may also be added for completeness. Functionally, however, `exists` would almost always produce the same result as `notEmpty`. Its distinct value is limited to cases where a target exists but has an empty value.

Alternatively, please change the binding of `assert.operator` from `required` to `extensible`, allowing an Implementation Guide to introduce `notExists` and, if needed, `exists`.
