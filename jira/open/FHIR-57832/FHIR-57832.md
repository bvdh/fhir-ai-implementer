- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: The definition is "The request represents a request/demand and authorization for action by the requestor."

Some readers are interpreting the definition to mean that a Request by itself is not only an authorization but also an explicit request for fulfillment. However, that's not what the workflow methodology says. A request for fulfillment always requires something extra - a Task, message, operation, tag, or something else. We need to revise the definition to remove this confusion.

My initial proposal: "The request represents an authorization for action with an expectation it will be acted on - though standard request fulfillment mechanisms are still necessary to initiate that action."

I'm not in love with the wording, so happy for any adjustment that provides the needed clarification.
