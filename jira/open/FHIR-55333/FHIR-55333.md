## Comments

### 1. Jose Costa-Teixeira - 2026-10-06

Requesting to revisit this disposition. The resolution ("We will move non-example-binding value sets to THO") uses the binding strength as the criterion; both value sets listed have example bindings, so as voted nothing would move. The criterion should be whether the content is appropriate for production use: a value set with an example binding that is fit for production use may be bound more tightly downstream (in IGs or other specifications), so it should be maintained in THO. Content that is only illustrative should be marked experimental = true (value set and code system) and stay in core.

Proposed revised resolution (Persuasive with Modification): value sets and code systems appropriate for production use move to THO, whatever their binding strength; illustrative content is marked experimental and stays in core.

Impacted value sets:

medication-admin-category (inpatient, outpatient, community, discharge) – bound to MedicationAdministration.category, example binding; experimental (value set / code system): false / false. Move to THO, aligned with the other category code systems (see below).
administration-subpotent-reason (partialdose, vomited, coldchainbreak, recall, adversestorage, expired) – bound to MedicationAdministration.subPotentReason, example binding; experimental (value set / code system): true / false. Move to THO. Real-world reasons, fit for production use; set experimental = false on the value set.

Category alignment: the MedicationRequest, MedicationAdministration and MedicationDispense category code systems have the same four codes (inpatient, outpatient, community, discharge) with the same definitions, differing only in "requests / administrations / dispenses"; MedicationStatement already reuses the MedicationRequest value set, and THO already has http://terminology.hl7.org/CodeSystem/medicationrequest-category (from R4). Proposal: one THO code system and value set for the setting of medication use (e.g. "Medication Use Setting"), with resource-neutral definitions (including discharge), bound to all four category elements; the three core code systems are removed and the existing THO medicationrequest-category is deprecated with a mapping to the new one. (Alternative: reuse the THO medicationrequest-category for all four.)
