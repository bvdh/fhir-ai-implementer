- **Description**: FHIR provides the ability upon search, but not read, to use the _profile parameter to retrieve only those resources that are tagged with that profile. Considering the meaning and use of the _profile parameter for both "FHIR facade" or "FHIR persisted" approach, we find this to not be sufficient to enable validation of the content returned by a read operation, with or without that resource instance's Resource.meta.profile being valued, against a particular profile. Being able to convey that with a parameter would greatly improve one's ability to get all resources that conform to that profile, whether they were tagged with it or not.

We proposed adding a new parameter named, e.g., "_conform", that when valued causes search or read operations to return all resource instances that conform to the profile included. This parameter should be non-repeating and include a version to enable more specificity where needed, defaulting to a version per the server's capability statement. If the requested profile is not recognized, unavailable, not supported, a 422 will be returned. ++ The parameter should be permitted for READ, SEARCH, and PATCH.

For further context, when using the "FHIR facade" approach, data may or may not be updated through the FHIR server and may or may not have been tagged with the profile(s) that created and/or updated the data. Thus, using _profile in the "FHIR facade" approach would only get a subset of the applicable data that could be considered appropriate for the search or read. Using the proposed _conform parameter to indicate the profile(s) that the data being searched or read needs to conform to the profile(s) removes that limitation and enables reading or searching the full data set that is considered relevant. Having both parameters still available can accommodate use cases where either one truly only wants to read or search data that was written/updated in accordance with a specific profile and nothing else (assuming that the profile tags were persisted which in practice may not hold as well as one would want to) or get data that conforms to the profile.
