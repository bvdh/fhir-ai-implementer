# FHIR-34205: Add ServiceRequest.status values

- **Raised in Version**: R5
- **Work Group**: Orders & Observations
- **Related Artifact(s)**: ServiceRequest
- **Grouping**: COW, LAB_Call
- **Description**: To enable follow-up steps on a ServiceRequest with a status of complete (e.g., the results were communicated as final but the ordering provider wishes the observation to be re-interpreted in light of, e.g., the patient's clinical profile and/or demographic data updates) additional status codes are needed that can be valued after a SeviceRequest.status was set to "complete".

Additionally it is then necessary to indicate the reason why the related observation(s) need to be re-interpreted.

Once the re-interpretation is completed, the ServiceRequest.status is set back to "complete".

Proposal is to add:

ServiceRequest.status codes for:

under-revision - a change to AOEs or demographics yielded the re-interpretation
under-review - the results do not appear to fit the patient's clinical profile

ServiceRequest.reason.concept codes for:

clinical-reinterpretation - Re-interpretation (clinically questioned) + text ( valid only with under-review)
demographic-reinterpretation - Re-Interpretation (demographic change) (valid only with under-revision)
ask-at-order-entry-response-reinterpretation - Re-interpretation (AOE change) (valid only with under-revision)

Note for AOEs the Observation.status would have changed to corrected/amended.

ServiceRequest.reason comments addition:

When a re-interpretation is requested, the observation(s) that are to be re-interpreted should be included as a reference in SeviceRequest.reason.reference.

### 13. Andrea Pitkus - 2023-02-09

There are multiple CLIA requirements that don't appear in the proposal above.

How would approach above meet k3 below in maintaining duplicate reports? The original should be maintained as well as issuance of a new report with corrections for physician requests after a report has been completed.

https://www.ecfr.gov/current/title-42/chapter-IV/subchapter-G/part-493#p-493.1291(k)

(k) When errors in the reported patient test results are detected, the laboratory must do the following:
(1) Promptly notify the authorized person ordering the test and, if applicable, the individual using the test results of reporting errors.
(2) Issue corrected reports promptly to the authorized person ordering the test and, if applicable, the individual using the test results.
(3) Maintain duplicates of the original report, as well as the corrected report.

It should be clearly indicated that a referring laboratory "must not revise results" per https://www.ecfr.gov/current/title-42/chapter-IV/subchapter-G/part-493#p-493.1291. Any updated/changed results would need to be from the performing laboratory to be compliant.

Where there is a concern that results may have an error that needs to be addressed, orders are not re-opened as suggested here. Rather results (which are reported) are updated and clearly indicate the original result and correct result value), In Pathology and Radiology, this is usually achieved by issuing an amended report (even if demographics have changed).

This is a significant CLIA requirement for lab results, and impacts other clinical areas like radiology (even though CLIA doesn't apply to this field, CLIA best practices can help radiology provide better quality results too.)

This are many impacts/triggers (i.e. billing charges are dropped by previous actions and the patient may be charged twice) by the proposed action that must be considered too. Any alerts or triggers firing off of a completed order would also be impacted. For example, when incorrect demographics were "corrected" in a radiology report, "re-completing" triggered another letter sent to the patient indicating they needed a biopsy even though they already had the biopsy completed in their record. (A patient safety issue/poor design issue.)

Completed orders should not be "re-opened and re-completed."
