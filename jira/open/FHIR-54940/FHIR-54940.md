- **Description**: Cardinality of the target components is not defined in the spec.
Specifically unclear if a context/element is required or not.

Add a dedicated section describing how when target elements are created, and their values set from the source - covering what "auto-created elements" means.
How types are determined in the auto-creation.
When explicit create() is needed - only with choice types?
Interaction with underlying type constraints

The Target Transform description doesn't contain the fhirpath usage as it does in the Source Context. Could do as adding an optional line to the definiton (and include optional markers):

[{*}context.element ={*}] transform_code(parameters...) [{*}as variable{*}] {list_modes}
or
[context.element =] (FHIRPath) [as variable] {list_modes}

Although this doesn't feel clear enough either.
