- **Resolution Description**: renderedInstruction stays markdown. FHIR markdown does not support inline HTML: processors SHALL treat embedded tags as string content, so content like the HTML comment in the example is displayed, not hidden (see datatypes.html, markdown). Markdown allows the simple formatting that makes dosage instructions readable (line breaks between steps, emphasis on warnings), and text without markup is valid markdown.
We will add a comment to the element, pointing to the markdown datatype.
- **Request in-person**: Daniel Zhang, LucasRizzolo
- **Description**: Suggestion: DosageDetails.renderedInstruction should simply be a string datatype, rather than the [FHIR markdown |Datatypes - FHIR v6.0.0-ballot3] datatype.

Per [link title|Dosage - FHIR v6.0.0-ballot3], it is important to display the renderedInstructions to the end user. Recall that FHIR markdown is defined to be a string that may optionally be rendered using the Github-Flavored Markdown extension of the CommonMark format.

As such, the information contained in these instructions should be simple for all humans to read, regardless of interpretation or optional rendering of this markdown.

As an extreme example, consider how differences in implementation may display the renderedInstructions differently to the end user:

As freetext:

YOU SHOULD <!-- NEVER --> TAKE MORE THAN ONE TABLET PER DAY

Render using Github-Flavored Markdown :

YOU SHOULD TAKE MORE THAN ONE TABLET PER DAY
