- **Description**: When shipping a diagnostic report, (a common occurrence) it is necessary to create a bundle for the clinical document that contains the referenced resources (.subject, .basedOn, .study, .results, .conclusionCode, .recommendation, .communication, .presentedForm, etc). Ideally this should be done in a uniform, predictable way since it will be conveyed to other hospitals/implementation spaces.

As a "wrapper", this bundle should have appropriate document management metadata (like .type, .subject, .status, .version, .date, .custodian, .consent, etc) and signature/attestation/security capability as provided by Provenance.

(For that matter, for sites still just creating PDF reports, it would also be useful to be able to create a clinical document bundle for DocumentReference that includes the DocRef resource and the referenced PDF and other resources and provides the same document management and provenance wrapper).

One approach would involve harmonizing the document management metadata with Composition and cloning the $document behavior.

A more foundational approach would involve splitting a Document resource off of Composition. Currently Composition tries to do two things at once: Provide the external document management functions & provide the internal document layout organization functions (.section, etc). By binding document bundle manifest construction to the .section.entry mechanism, document bundle creation and management is bolted to the use of .section mechanics which are not necessarily needed for DiagnosticReport (or DocumentReference). Composition is, of course, a very useful and sensible approach for a sizeable class of clinical documents.
