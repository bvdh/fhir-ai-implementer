# FHIR-39503: FHIR Package: Specifications to enable private package registries

## Metadata

- **Summary**: FHIR Package: Specifications to enable private package registries
- **Created**: 2022-11-28
- **Updated**: 2025-04-14
- **Resolved**: 2025-04-14
- **Status**: Waiting for Input
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Brian Kaney
- **Resolution**: Persuasive with Modification
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R4
- **Work Group**: FHIR Infrastructure
- **Related Artifact(s)**: ImplementationGuide
- **Resolution Description**: We will update the existing extension to add the proposed invariant
We will document (where?) that NPM scopes are supported (but not required) in HL7 packages.
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: It is common outside of FHIR to have both public and private registries for software artifacts (NPM, docker, etc). This pattern should be supported by FHIR packages. Advancing the specification to support external registries and npm scoped packages would enable this, and should lead to modifications in public (and private/commercial) FHIR tooling.
