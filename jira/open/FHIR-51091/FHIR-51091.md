- **Description**: This table covers 2 situations (with variant rules for first element and second element): Type definition and Constraint definition.

The code is presuming those correspond to "any type where kind = 'specialization'" and "any type where kind = 'constraint'"

However, I don't think that was our intention. We intended type definition to apply for kind=primitive type, complex type, and resource. But I'm pretty sure we didn't intend this to apply for logical models.

As enforced at the moment, the rule says we can't have minValue[x], maxValue[x], or maxLength when defining a logical model. However, that doesn't make sense. We do want that prohibition for resources and complex types because those are generic structures that shouldn't have such constraints. However, it's completely reasonable to have these things for logical models which might already be quite context-specific. And in practice we have these things on simple-types too. We use invariants to define them, but really things like id, string, etc. have maxLengths and our various integer types have minimum and maximum values.

The question is whether we can get away with this correction given that the page is already normative...
