- **Description**: status Value "cannot-be-obtained" and dataAbsentReason Overlap

Issue: The status code cannot-be-obtained semantically overlaps with dataAbsentReason. Both convey "why there's no value," but:

{{status = }}"cannot-be-obtained" is a workflow/resource-level statement
dataAbsentReason is a value-level statement

The current approach has been to use dataAbsentReason, which is extensively documented in the Observation's notes section.

{ "status": "final", "dataAbsentReason": {"coding": [
{"code": "error"}
]} }

This resource has been widely implemented, and there is no reason to introduce an alternative mechanism for communicating when a value cannot be obtained.

In addition, the "cannot-be-obtained" status value can produce contradictory results:

{ "status": "cannot-be-obtained", "valueQuantity":
{"value": 5.0, "unit": "mg/dL"}
}

Propose:

Remove the status value "cannot be obtained" because it is not needed and will cause confusion for implementers.
