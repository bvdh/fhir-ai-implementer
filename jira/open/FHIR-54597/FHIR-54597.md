- **Description**: Each step has relative time start/end, and there is instruction
"When a DosageDetails contains multiple steps, the steps are sequential - the dosage course follows through the steps one at a time. Each step has to specify an end condition - either by explicitly linking the step to some external event, or by specifying a limit on the timing of the event using either Timing.repeat.bounds[x] or Timing.repeat.count on the Timing data type."

The example 14.7.1.4 Example 3: Tapered dose, with some interlaced dosages also shows steps with repeat.count and repeat.boundDuration.

However, this creates a strong dependency on the list itself to ensure step ordering. There is no other reference on each step item to indicate that the step item itself has an important conditionality on the prior steps in the list being completed. This seems risky and a potential safety issue because as processing occurs on the list, the list ordering is not always guaranteed to keep sequence (e.g. lists processed asynchronously or with XSLT that does not make sequence guarantees). Further, if/when this sort of error occurs it would be hard to trace or identify that the sequence was lost. So, while it may be possible for some implementations to take precautions and ensure sequencing in the list processing, the risk is high for an error to occur that results in dramatically different clinical meanings. I thus strongly would favor adding back an explicit sequence identifier on the step so that if the list was processed where sequence was not kept it would at minimum become apparent what happened.
