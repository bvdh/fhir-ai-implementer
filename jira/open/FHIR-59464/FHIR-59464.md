- **Resolution Description**: We note that the current Encounter.specialCourtesy combines two orthogonal concepts:

The categorization of the person (VIP, board member)
The courtesies that person gets (normal, profession, extended)

We also have the standard patient-importance extension on the Patient that is entirely focused on #1 (the person categorization) and it has a very clean value set.

We propose to make a few updates to Encounter.specialCourtesy:

Update the Comment to clarify that this element is only about the courtesies. And attributes like "VIP" should be in the patient-importance extension.
Update the Special Courtesy value set to remove the STF and VIP codes. This makes the value set clearly about the courtesies, and not the person categorization. We note that is already UP-774 to add definitions to the codes that remain.

We note this property has been in the spec since DSTU2. However, we have gotten very little feedback, so we don't have a good signal on whether it is widely used successfully, or never used because of it's odd combination of concepts.
- **Change Category**: Clarification
- **Change Impact**: Compatible, substantive
- **Description**: Encounter.specialCourtesy lists “VIP, board member”. The definition repeats these and adds professional courtesy: no definition conflict. The preferred ValueSet includes VIP (very important person), STF (staff), PRF (professional courtesy), EXT, NRM, and UNK. Board membership names a relationship; neither VIP nor staff classification follows without local policy. Clarify that policy or use professional courtesy instead. Preserve the benefits-versus-record-security explanation; resolve this ambiguity before list completion.

+ are there any appropriate special courtesies for home encounters?
