- **Resolution Description**: Motion to clarify that BDP is an instance resource with this addition in scope and usage:
BiologicallyDerivedProduct represents an identifiable physical product or material instance. It is not intended to define a reusable product specification, manufacturing recipe, or class of biologically derived products.

A separate Jira will capture the evaluation of a definitional resource in the Incubator.
When such a canonical resource is available the BDP instance (and other resources) will need to be able to point to said resource.
- **Change Category**: Enhancement
- **Change Impact**: Non-substantive
- **Description**: Recommend adding to scope and usage a statement such as:

BiologicallyDerivedProduct represents an identifiable physical product or material instance. It is not intended to define a reusable product specification, manufacturing recipe, or class of biologically derived products.

## Comments

### 1. David Barwin - 2026-10-05

The detailed description of BDP clearly positions it as representing an instance of a biologically derived product; it is not currently described as a hybrid instance/definitional resource. That said, given the limited known implementer demand for a definitional representation, this may be better explored through profiling and/or extension space before introducing a new resource.

FHIR has previously supported both physical instances and definitional kinds within a single resource where the underlying information model substantially overlapped. Device, prior to the introduction of DeviceDefinition, provides a useful precedent. A profiled BDP "kind" representation could similarly be explored in the OO Incubator before determining whether a separate BiologicallyDerivedProductDefinition resource is warranted.

A definitional BDP profile might initially constrain the resource along these lines:

BiologicallyDerivedProduct definition-like profile

biologicalSourceEvent 0..0
collection 0..0
division 0..0
expirationDate 0..0
parent 0..0
identifier restricted to type/catalog identifiers
productCode 1..1
property 0..*

If the distinction cannot be adequately conveyed through the profile itself, an extension indicating whether the BDP represents an instance or a kind could also be considered.

This results in a fairly limited definitional representation, which may itself be informative. If known definitional use cases can be satisfied by a constrained BDP with productCode, property, identifiers, and relatively little additional structure, there may not yet be sufficient justification for introducing a separate definitional resource. Conversely, Incubator testing may identify additional common definitional requirements and provide the evidence and requirements for a future BiologicallyDerivedProductDefinition resource.
