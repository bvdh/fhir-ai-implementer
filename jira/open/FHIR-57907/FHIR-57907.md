- **Specification**: FHIR Core (FHIR)

- **Related Artifact(s)**: Specimen
- **Grouping**: Specimen_Call
- **Description**: This ballot adds a new Specimen.processing.performer element with reference targets Practitioner | PractitionerRole | Patient | RelatedPerson. In the same ballot, Specimen.collection.collector gained Organization as a target. The result is an inconsistency between two closely parallel elements that were both touched in this cycle: you can say an organization collected the specimen, but not that an organization processed it.

In practice, specimen processing is very often attributable to a laboratory organization rather than a specific named person, and increasingly to automated instrumentation rather than a human at all. The current target list can't express either case.

Proposed resolution:
Align processing.performer's reference targets with collection.collector by adding Organization, and additionally add Device to cover automated/instrument-driven processing.
