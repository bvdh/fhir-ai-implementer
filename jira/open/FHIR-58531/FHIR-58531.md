- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Outstanding Negatives**: Normative
- **Related Artifact(s)**: MessageHeader
- **Request in-person**: Vassil Peytchev
- **Description**: The MessageHeader.response.code element has a required biding to the response-code value set. The desciption of the fatal-error code states:
The message was rejected because of a problem with the content. There is no point in re-sending without change. The response narrative SHALL describe the issue.
The following proposed change clarifies the phrase "problem with the content" and replaces the reference to "response narrative" with the correct "response details"
The message was rejected because of a problem with the content, which includes problems beyond just conformance with the FHIR standard or one or more FHIR Implementation Guides (for example, the presence of an unrecognized patient identifier in the content). There is no point in re-sending without change. The OperationOutcome resource referenced in MessageHeader.response.details SHALL describe the issue(s).

## Comments

### 1. Brian Frankl - 2026-09-01

vassil - INM reviewed this tracker and believe this clarification has already been addressed in FHIR tracker https://jira.hl7.org/browse/FHIR-55247 making it clear the MessageHeader.response.details will contain specific details instead of response narrative.

As MessageHeader.response.details can only be a OutcomeOperations reference, inclusion of that language does not seem to be necessary. Additionally, we feel content examples are not needed in the error description as it will be implementation specific what is considered a content problem.

This tracker has been added to our Tuesday Q2 quarter agenda for the WGM. Please let us know if our previous tracker addresses this request and you withdraw FHIR-58531.
