- **Description**: Comment

The current R6 ballot text describing additional bindings conflates two distinct concepts:

Binding strength (required / extensible / preferred / example), which defines conformance and validation behavior, and

Binding purpose (e.g., component, minimum, current, ui, starter), which describes why an additional value set is supplied and how it is intended to be used.

These concepts are orthogonal, but are currently intermingled in the same narrative and table, making it difficult for IG authors, implementers, and tooling developers to understand which aspects affect conformance versus documentation or guidance.
Why this matters

The lack of clear separation leads to:

inconsistent modeling patterns across IGs,

unclear validator behavior when additional bindings are layered on top of extensible base bindings, and

implementer confusion about whether a given additional binding is enforceable, informational, or application-level guidance.

Requested change

Please revise the Terminology Bindings section to:

explicitly separate binding strength from binding purpose (e.g., distinct tables or clearly delineated subsections), and

state clearly that binding strength and binding purpose are independent concepts, with defined relationships where applicable.
