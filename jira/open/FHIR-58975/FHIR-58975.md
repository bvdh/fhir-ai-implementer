- **Description**: Affected elements:

`TestScript.variable.description`
`TestScript.variable.hint`

In R5, `variable.description` is defined as:

> A free text natural language description of the variable and its purpose.

`variable.hint` is defined as:

> Displayable text string with hint help information to the user when entering a default value.

The distinction between these elements is not sufficiently clear. Both can contain user-facing information about a variable, but the specification does not define:

whether an implementation should display one or both elements;
which element takes precedence;
whether `hint` is only applicable when `defaultValue` is present;
what information belongs in `hint` rather than `description`.

For variables with a `defaultValue`, Conformancelab currently displays `description` in its user interface, rather than `hint`. This is sufficient to explain the variable and the value to the user. Supporting a second text element would add another representation without a clearly distinct purpose.

The current Testing IG retains both elements with the same descriptions, so it does not resolve this ambiguity.

To keep TestScript lean and unambiguous, deprecate `TestScript.variable.hint` and use `TestScript.variable.description` as the authoritative human-readable explanation of a variable, including information relevant when supplying or reviewing its value.
