# FHIR-59411: Regex references need to be constraints

## Metadata

- **Summary**: Regex references need to be constraints
- **Created**: 2026-09-23
- **Updated**: 2026-09-23
- **Status**: Triaged
- **Project**: FHIR Specification Feedback
- **Type**: Technical Correction
- **Reporter**: Lloyd McKenzie
- **Resolution**: Unresolved
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R5
- **Work Group**: FHIR Infrastructure
- **Related Page(s)**: Datatypes
- **Description**: The datatypes still have regex extensions that are showing up in the publication, and regex is deprecated. Specific issues in:

base64binary
boolean
canonical
code
date
datetime
decimal
id
instant
integer
integer64
markdown
oid
positiveint
string
time
unsignedint
uri
url
uuid

All need to be exposed as invariants. If you don't want a specific human message, you can say "The syntax of the value does not comply with FHIR requirements", though it'd be better if there were more specific wordings per datatype

Also, there are regexes in resource definitions (e.g. Questionnaire) that aren't showing up in the published spec and I'm not sure why.
