- **Resolution Description**: The requested new expression will also not work when url is not equal is not going to detect that the targets are indeed the same (e.g. urls to different versions of the same resource). Looking at all of the invariants on Provenance, they are all susceptible to various situations where they will not perfectly find an inappropriate relationship. Further discussion determines that they all could be removed without losing any useful functionality. So the recommendation is to remove all 4 invariants and add a narrative paragraph that warns about the appropriate use of onBehalfof.
- **Resolution Vote**: Dave Pyke / Grahame Grieve : 14-0-1
- **Vote Date**: 2026-09-23
- **Change Category**: Correction
- **Change Impact**: Compatible, substantive
- **Description**: All the constraints use .resolve(), but this function may not be evaluated correctly or even supported.

Consider simpler expressions comparing reference values directly:

e.g., for "Who and onBehalfOf cannot be the same"

who.reference != onBehalfOf.reference or who.identifier != onBehalfOf.identifier

NOTE: I have not tested this expression, so it needs to be verified
