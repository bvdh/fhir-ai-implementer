- **Description**: While updating the PHD IG I noticed that a Quantity is not required to have a value. In fact it can be any subset of the defined elements {value, comparator, unit, system, code}.
This makes it (theoretically) possible to define a clock accuracy with just a unit code of "s" for seconds or "Cel" for Celsius for example. Clearly this needs to be constrained in profiles using Quantity. Maybe the datatype itself could have a constraint that it should have a value and a note that without unit or code it is assumed to be dimensionless.

Next, when such Quantity without value is used as a valueQuantity in an Observation resource, does this mean that there shall be no DataAbsentReason, although the data has no value? Should there be a constraint in Observation on valueQuantity to have a value or should the constraint on DataAbsentReason - obs-6:

Observation.dataAbsentReason SHALL only be present if Observation.value[x] is not present

be modified? If so, the corresponding rule for component.dataAnsentReason needs modification as well.
