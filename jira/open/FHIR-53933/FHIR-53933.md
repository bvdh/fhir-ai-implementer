# FHIR-53933: Discretely define "hierarchical" circular references for use by above and below modifiers

- **Resolution Description**: This is tracked via the http://hl7.org/fhir/StructureDefinition/structuredefinition-hierarchy extension.

Elements with this extension and a value of true are allowed to use the :above and :below modifiers.

FHIR-I will also review the Circular Resource References list for elements that:

have this extension with a value of false, or
allow referencing the same resource type but do not have this extension
and will file tickets to other WGs as necessary.
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: The concept of "hierarchical" resource references are defined on references to the same resource type, and are used by the :above and :below modifiers to search transitively through the hierarchy. The documentation points out that some circular references correspond with a hierarchical structure, and some do not.

This seems like something that should be able to be defined through discrete element-level metadata. If it can't be reliably determined for the base spec, there should be a standardized way to define these relationships at the profile level.
