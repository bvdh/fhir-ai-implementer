- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: Financial Mgmt
- **Outstanding Negatives**: Normative
- **Related URL**: https://hl7.org/fhir/6.0.0-ballot5/paymentreconciliation.html
- **Related Artifact(s)**: PaymentReconciliation
- **Related Section(s)**: 16.9.4
- **Grouping**: FM-R5-ToBeApplied
- **Resolution Description**: Move allocation.type and allocation.amount to a new backbone element, which we propose calling targetAction, with cardinality 0..* to support multiple payment expressions on the same target, e.g., claim.
Within the targetAction backbone element the allocation.targetAction.type and allocation.targetAction.amount have a cardinality of 1..1.
- **Resolution Vote**: Rick G eimer / Celine Lfebvre : 3 - 0 - 0
- **Vote Date**: 2026-09-23
- **Change Category**: Enhancement
- **Change Impact**: Non-compatible
- **Applied for Version**: R6
- **Description**: While .allocation can support repeating for each line item, it seems like it should allow for multiple items in one allocation (claim). It should allow for multiple actions against each item. For example, there might be multiple adjustments and a payment. This would also require the Payment Type to move to the repeats under the item level.

- **Jira**: https://jira.hl7.org/browse/FHIR-58201

## Comments

### 1. Paul Knapp - 2026-09-15

Consider moving allocation.type and allocation.amount to a new backbone element 0..* to support multiple payment expressions on the same target, e.g. claim.
