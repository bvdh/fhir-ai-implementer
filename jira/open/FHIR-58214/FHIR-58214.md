- **Description**: FHIR-53981 renames Goal.statusDate to Goal.achievementStatusDate and Goal.statusReason to Goal.lifecycleStatusReason.

However, the previous definition of statusDate was broader:

"Identifies when the current status. I.e. When initially created, when achieved, when cancelled, etc."

The examples include events that correspond to both lifecycle status (initially created, cancelled) and achievement status (achieved). As a result, previous implementations may reasonably have populated statusDate with dates related to lifecycleStatus.

With the R6 change, achievementStatusDate is only associated with achievementStatus. This may cause difficulty when migrating to R6 from previous versions. The following values could be part of a valid Goal in previous versions:
lifecycleStatus = cancelled

statusDate = 2026-01-15

achievementStatus = (absent - since achievementStatus is optional)
In R6, there is no element to preserve the previous meaning of statusDate. Mapping the date to achievementStatusDate would change its meaning, while omitting it would lose information.

Questions:

Previous versions appear to allow statusDate to represent the effective date of either the current lifecycleStatus or achievementStatus. Is that interpretation correct?
If so, how should implementations preserve lifecycleStatus dates when converting to R6, where achievementStatusDate no longer accommodates that use case and no corresponding lifecycleStatusDate exists?
