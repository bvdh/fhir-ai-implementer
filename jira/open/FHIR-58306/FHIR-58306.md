- **Description**: I totally agree with the need to reflect Requirements in FHIR, I'm worried about the maturity of this resource and the need for this resource to be part of the normative FHIR-core.

Resource management is an essential part of the development and maintenance of (medical) devices. The field of requirement-management has several well established standards for defining and maintaining requirements (e.g. https://www.iiba.org/babok-guide/babok-guide-v2/babok-guide-online/chapter-one-introduction/1-3-key-concepts.aspx and https://standards.ieee.org/standard/610.12-1990.html, ISO_IEC_IEEE 29148_2018, ISO_IEC_IEEE 29148_2018).

Please ensure the requirements definition is compatible with these standards and supports the different fields, links and defined requirement management operations. The resource definition should state in what way it is compliant with such standards.

The resource holds many requirements related fields but a description of the overall strategy on how each resource field should be used and what a certain field means is underspecified and should be provided.

As this is substantial work that is unlikely to be completed in a mature enough format in the timeframe of the R6 release, I suggest to move this resource to additional resources .
