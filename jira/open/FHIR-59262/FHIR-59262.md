- **Resolution Description**: Will put a constraint on item that mirrors que-18a and que-18b but applies to enableWhen.

Will also correct all three to handle the fact dateTime is not lowercase in the value set by changing `('type', type)` to `('type', type.lower())`
- **Resolution Vote**: Brenin Rhodes/Paul Lynch: 2-0-0
- **Vote Date**: 2026-10-01
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: There is currently no constraint on the Questionnaire.item.enableWhen.answer[x]element requiring it to be of the same datatype as the item it references.

If a mismatch exists (see the example below), the validator does not reject the questionnaire (I believe it should), but then fails when validating a valid instance because of a datatype mismatch. I'll file a separate GH ticket against the validator, but I believe the spec should also be updated to make this requirement explicit.

Example questionnaire:

{
"resourceType": "Questionnaire",
"id": "q",
"url": "http://foo",
"version": "1",
"name": "example",
"status": "active",
"item": [
{
"linkId": "areYouOk",
"text": "Are you ok?",
"type": "coding",
"required": true,
"answerOption": [
{
"valueCoding": {
"system": "http://answer",
"code": "yes",
"display": "Yes"
}
},
{
"valueCoding": {
"system": "http://answer",
"code": "no",
"display": "No"
}
},
{
"valueCoding": {
"system": "http://answer",
"code": "maybe",
"display": "Maybe"
}
}
]
},
{
"linkId": "areYouOkDetails",
"text": "Details",
"type": "string",
"enableWhen": [
{
"question": "areYouOk",
"operator": "=",
"answerString": "yes"
}
],
"enableBehavior": "all",
"disabledDisplay": "hidden",
"required": true
}
]
}

Note the enableWhen->answerString in the second question, although the referenced first question has a datatype of Coding.
