- **Resolution Description**: Location.status - this is a required code binding, and will remain in the core spec.

Location.operationalStatus - already in THO

Location.code - this will move to THO, but I suspect it might already be there, and we just need to point to it.

Location.mode - this is a required code binding, and will remain in the core spec.

Location.type - already in THO

Location.form - the code system is already THO, and the CLD is all codes, so we'll move the value set over to THO.

Location.characteristic - We will rename the value set from http://hl7.org/fhir/ValueSet/location-characteristic to http://hl7.org/fhir/ValueSet/location-characteristic-example This value set will remain in the core spec. The code system will also remain in the core spec.

- **Description**: The Location references several value sets that are potential candidates for migration to THO. While value set migration is not required, if it's realistic for the value set definition to need to change in the coming years, or the value sets might be useful in CDA, V2 or other specs, migration should be considered. Specifics: CodeSystem: location-characteristic (LocationCharacteristic) referenced by ValueSet location-characteristic bound to element Location.characteristic;
