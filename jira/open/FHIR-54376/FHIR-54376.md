- **Resolution Description**: `packageSize` and `instance` are not overlapping and both are kept. `instance` is used only when the Medication represents a physical product instance, typically a packaged product, as opposed to an abstract definition of a medication (for example, a product code used for prescribing), which has no `instance`. `packageSize` describes how much medication the package contains, and can be used in either case. We will update:

*Medication.instance* short: "Details about a physical instance of the medication"
*Medication.instance* definition: "Information that applies to a physical instance of the medication, typically a packaged product, such as its serial number, lot number and expiry date. A Medication that represents an abstract definition of a medication rather than a physical product does not have an instance."
*Medication.packageSize* comment: add "packageSize describes the contents of the package as a product. Details of a specific physical package, such as lot number and expiry date, are in Medication.instance."
- **Description**: New packageSize backbone added in R6:

numberOfItems: "The number of items in the package"
amountPerItem: "The amount per each item, e.g. 10 ml / vial"

Meanwhile, instance is defined as: "Information that only applies to packages"

Both relate to package information so propose either :

Consolidate the package information by moving packageSize under instance
Clarify the difference and when to use packageSize vs instance for package-related data.
