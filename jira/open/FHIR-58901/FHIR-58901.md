- **Description**: the definition of ConceptMap.additionalAttribute.type does not define what the meaning of a attribute with type code is.

We should define that if the type is code, then it's a code in either the source or target code system depending on whether it's a dependsOn or a product

We could also consider defining a system like in ConceptMap.propertyDefinition, and saying that the default only applies if there's no system
