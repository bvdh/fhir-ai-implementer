- **Resolution Description**: When FHIR-56428 is applied (renaming MedicationDispense.notPerformedReason to MedicationDispense.statusReason), we will:

Update MedicationDispense.statusReason:

Short: "Reason for current status"
Definition: "Captures the reason for the current status of the MedicationDispense."
Comment: "This is generally used for statuses that indicate that the dispense was not performed, was paused or did not complete as intended, such as cancelled, on-hold, unfulfilled or declined, and when a dispense resumes, but it can be used with any status. The reason for dispensing the medication is not conveyed here."
Cardinality and type are unchanged: 0..1 CodeableReference(DetectedIssue).

Update the MedicationDispense Status Reason Codes code system and value set:

Change their descriptions to: "Reasons for the current status of a medication dispense, including reasons for not performing, pausing or resuming the dispense."
Add the codes:

patient-request (Patient request): The status was changed at the request of the patient or their representative, for example to pause, postpone or resume the dispense.
awaiting-clearance (Awaiting clearance): The dispense is waiting for a required clearance before it can continue, such as a prior authorization, payer approval, payment, or a regulatory or pharmacist check.
awaiting-prerequisite (Awaiting prerequisite): The dispense is waiting for another activity to be completed first, such as a laboratory result, a clinical assessment, a procedure or another treatment.
issue-resolved (Issue resolved): The issue that caused the dispense to be put on hold has been resolved, and the dispense can resume.

Update the examples that use notPerformedReason to use statusReason:

medicationdispense0303 (on-hold, DetectedIssue reference)
medicationdispense0334 (declined, outofstock; also add the missing code system URI)
medicationdispense0335 (cancelled, frr02)

Map Event.statusReason to MedicationDispense.statusReason in the Event pattern mapping, update the R4 to R6 element map so that R4 MedicationDispense.statusReason[x] maps to statusReason, and add a note on the rename to the R5 to R6 version changes.

If the code system is moved to THO under FHIR-55334 before this is applied, the new codes are added in THO instead.
- **Description**: FHIR-56428 decides the rename to statusReason and the updated value set, but doesn't give the element wording or the new codes. The current definition ("…why a dispense was not performed") no longer fits. The existing codes only cover reasons for not dispensing.

Proposed resolution:

Element wording. Short "Reason for current status", plus a new definition and comment. The comment says any status can have a reason, typically not performed, paused or resumed. The type stays as it is today, 0..1 CodeableReference(DetectedIssue).

Value set and code system.

New description: reasons for the current status of a dispense, including not performing, pausing or resuming it.
Four new codes: patient-request, awaiting-clearance, awaiting-prerequisite and issue-resolved, each with a definition.
Existing codes that already work for on-hold: hospadm, surg, clarif and outofstock.

Follow-on edits.
Update the three examples that use the old name. - medicationdispense0303, medicationdispense0334, medicationdispense0335
Map Event.statusReason.
Update the R4→R6 element map.
Add a version-change note for the rename from R5.
