- **Request in-person**: Linda Michaelsen
- **Description**: In reviewing several Resources including Coverage, it looks like best practice is for .statusReason to be a CodeableConcept. Text is always a challenge. It can be used in a CodeableConcept but once an element is Normative of string, it is much more challenging to make it a CodeableConcept.

Consider changing .statusReason in all the following Resources to CodeableConcept with an example binding

These resources still have "statusReason" as string.
CoverageEligibilityRequest
CoverageEligibilityResponse
Claim
ClaimResponse
PaymentNotice
PaymentReconciliation
ExplanationOfBenefits
