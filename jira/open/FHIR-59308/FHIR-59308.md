# FHIR-59308: MeasureReport.reporter does not allow for an AI system to be the reporter

## Metadata

- **Summary**: MeasureReport.reporter does not allow for an AI system to be the reporter
- **Created**: 2026-09-20
- **Updated**: 2026-10-16
- **Resolved**: 2026-09-21
- **Status**: Resolved - change required
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Grahame Grieve
- **Resolution**: Persuasive
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: Clinical Quality Information
- **Related Artifact(s)**: MeasureReport
- **Resolution Description**: We agree to add Device as a reporter. We will add a note that states AI might be a legitimate medical provider in some circumstances. For example, currently refills are being processed using AI.

We will also make sure that the specification is clear that the reporter is the attributable entity.
- **Resolution Vote**: Ben Hamlin/Bryn Rhodes:24-0-1
- **Vote Date**: 2026-10-16
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: MeasureReport.reporter does not allow for a Device to be the reporter of a MeasureReport, and this should be fixed.

Note about AI participations: the question is not whether we would like an AI to do this, or think that it's good practice. The question is: is it impossible for an AI to do this? if it's not, then Device should be one of the possibilities. Note that the participant pattern includes Device (partly for this reason), so not allowing it is also a deviation from the workflow pattern anyway.
