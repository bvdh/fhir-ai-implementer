- **Description**: The MedicationRequest references several value sets that are potential candidates for migration to THO. While value set migration is not required, if it's realistic for the value set definition to need to change in the coming years, or the value sets might be useful in CDA, V2 or other specs, migration should be considered. Specifics: CodeSystem: medicationrequest-category (MedicationRequestCategoryCodes) referenced by ValueSet medicationrequest-category bound to element MedicationRequest.category; CodeSystem: medication-intended-performer-role (MedicationIntendedPerformerRole) referenced by ValueSet medication-intended-performer-role bound to element MedicationRequest.performerType; CodeSystem: medicationrequest-dispenser-instructions (MedicationRequestDispenserInstructions) referenced by ValueSet medicationrequest-dispenser-instructions bound to element MedicationRequest.dispenseRequest.dispenserInstruction; CodeSystem: medication-dose-aid (MedicationDoseAid) referenced by ValueSet medication-dose-aid bound to element MedicationRequest.dispenseRequest.doseAdministrationAid;

## Comments

### 1. Jose Costa-Teixeira - 2026-10-06

Requesting to revisit this disposition. The resolution ("We will move non-example-binding value sets to THO") uses the binding strength as the criterion. The criterion should be whether the content is appropriate for production use: a value set with an example binding that is fit for production use may be bound more tightly downstream (in IGs or other specifications), so it should be maintained in THO. Content that is only illustrative should be marked experimental = true (value set and code system) and stay in core.

Proposed revised resolution (Persuasive with Modification): value sets and code systems appropriate for production use move to THO, whatever their binding strength; illustrative content is marked experimental and stays in core.

Impacted value sets:

medicationrequest-category (inpatient, outpatient, community, discharge) – bound to MedicationRequest.category, MedicationStatement.category, example binding; experimental (value set / code system): false / false. Use THO. Already in THO (http://terminology.hl7.org/CodeSystem/medicationrequest-category); align with the other category code systems (see below).
medication-intended-performer-role (registerednurse, oncologynurse, paincontrolnurse, physician, pharmacist) – bound to MedicationRequest.performerType, extensible binding; experimental (value set / code system): false / false. Move to THO while the binding is extensible. If FHIR-57350 makes the binding example and the group sees the list as illustrative, mark it experimental and keep it in core instead.
medicationrequest-dispenser-instructions (dispense-as-written, split-pack-allowed, counsel-patient, additional-monitoring-required) – bound to MedicationRequest.dispenseRequest.dispenserInstruction, example binding; experimental (value set / code system): false / false. Move to THO. Fit for production use.
medication-dose-aid (blisterpack, dosette, sachets) – bound to MedicationRequest.dispenseRequest.doseAdministrationAid, MedicationDispense.doseAdministrationAid, example binding; experimental (value set / code system): true / false. Stay in core as illustrative: three codes, not a complete list for production use; set experimental = true on the code system as well. (If the group sees it as production content, move to THO instead.)

Category alignment: the MedicationRequest, MedicationAdministration and MedicationDispense category code systems have the same four codes (inpatient, outpatient, community, discharge) with the same definitions, differing only in "requests / administrations / dispenses"; MedicationStatement already reuses the MedicationRequest value set, and THO already has http://terminology.hl7.org/CodeSystem/medicationrequest-category (from R4). Proposal: one THO code system and value set for the setting of medication use (e.g. "Medication Use Setting"), with resource-neutral definitions (including discharge), bound to all four category elements; the three core code systems are removed and the existing THO medicationrequest-category is deprecated with a mapping to the new one. (Alternative: reuse the THO medicationrequest-category for all four.)
