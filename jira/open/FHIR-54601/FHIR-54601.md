- **Resolution Description**: We will add additional information in the "Using FHIR types in expressions" section (after the table):

Note that not all FHIR types have the same level of precision/range as their fhirpath equivalent types.

The range of decimal in FHIR is 1e18 and FHIRPath is 1e28,
FHIRPath datetimes can contain partial times, whereas fhir datetimes can be partial dates, or include a complete date and time (including timezone).
Some use cases may need to craft expressions carefully to handle this difference.

- **Description**: There is a large difference in the range of decimal between FHIR (1e18) and FHIRPath (1e28). ### 5. Bryn Rhodes - 2026-01-20

The 18 digits comes from the minimum decimal representation in XML (https://www.w3.org/TR/xmlschema-2/#decimal)

The 28,8 in FHIRPath comes from bcd decimal representation ranges common in database management systems, 28 total digits, with 8 digits of scale.

Note that while both the XML and FHIRPath decimal representations characterize the limits as minimums that systems can provide more support for, FHIR explicitly characterizes the 18 digits as a maximum. Agree that the FHIRPath page in FHIR should be clear about what happens when a FHIRPath decimal value exceeds this range, but should it be an error? A warning?
