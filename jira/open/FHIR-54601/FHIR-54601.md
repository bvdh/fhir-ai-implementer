Use of FHIR Decimal

The range of decimal values is different between FHIR and FHIRPath.
The range of values supported by FHIR is 18 digits (which is based on the union of the XML decimal and double types), and the range of values supported by FHIRPath is 28 total digits, with 8 digits of scale (based on the binary coded decimal representation ranges common in database management systems).

This difference means that in some cases expressions MAY experience overflow situations.

As documented in the Math section of the FHIRPath specification, if operations cause arithmetic overflow or underflow the result will be empty {}.
An expression writer can use rounding, truncation or other similar functions to pre-emptively handle these cases if desired.

Need to describe scenarios:

valid in both (FHIR.decimal and System.decimal)
valid in FHIR.decimal but not System.decimal (e.g., too much precision)
valid in System.decimal but not FHIR.decimal (e.g., out of range)

### 3. Bryn Rhodes - 2026-01-20

The 18 digits comes from the minimum decimal representation in XML (https://www.w3.org/TR/xmlschema-2/#decimal)

The 28,8 in FHIRPath comes from bcd decimal representation ranges common in database management systems, 28 total digits, with 8 digits of scale.

Note that while both the XML and FHIRPath decimal representations characterize the limits as minimums that systems can provide more support for, FHIR explicitly characterizes the 18 digits as a maximum. Agree that the FHIRPath page in FHIR should be clear about what happens when a FHIRPath decimal value exceeds this range, but should it be an error? A warning?
