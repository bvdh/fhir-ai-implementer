# FHIR-26599: Description and definition of Bundle.entry.fullUrl is confusing

- **Related Artifact(s)**: Bundle
- **Related Section(s)**: http://build.fhir.org/bundle-definitions.html#Bundle.entry.fullUrl
- **Resolution Description**: The only situations where a URN is permitted as a fullUrl is when it is a urn:uuid and the Bundle is a message, document, or collection, or for transactions when the entry is performing a POST, [conditional update] or [conditional delete]. In all other cases, the expectation is that the fullUrl is an absolute URL (typically http/https). URLs SHOULD be resolvable, though servers might not support the read operation.

@grahame will write up a summary of what rules we express in different parts of the spec to make sure we don't contradict ourselves.
- **Change Category**: Clarification
- **Description**: It is not clear if there are legitimate exceptions between fullUrl being the endpoint of a resource accessible via the FHIR REST API (or another API), and it being a UUID in URN notation. The use of shall and should seems inconsistent.
