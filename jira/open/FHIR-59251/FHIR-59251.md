- **Description**: Affected elements and constraints:

`TestScript.setup.action.assert.expression`
`TestScript.setup.action.assert.minimumId`
`TestScript.setup.action.assert.validateProfileId`
`tst-5` for `TestScript.setup.action.assert`
`tst-6` for `TestScript.test.action.assert`
`tst-20` for `TestScript.common.action.assert`

In R5, constraints `tst-5` and `tst-6` explicitly allow `expression` to be combined with either `minimumId` or `validateProfileId`.

The corresponding constraints in the current Testing IG require the assertion elements to have a combined count of at most one. This prevents both combinations.

In these combinations, `expression` does not define a second assertion. It selects the input to which the `minimumId` comparison or profile validation is applied.

For example, a response may contain a Bundle while only one selected resource should be validated:

{
"expression": {
"language": "text/fhirpath",
"expression": "Bundle.entry.resource.where(resourceType() = 'Patient' and id = 'example')"
},
"validateProfileId": "patient-profile"
}

Similarly, a selected resource may be compared with a minimum-content fixture:

{
"expression": {
"language": "text/fhirpath",
"expression": "Bundle.entry.resource.where(resourceType() = 'Patient' and id = 'example')"
},
"minimumId": "minimum-patient"
}

Please restore these combinations in `tst-5`, `tst-6` and `tst-20`, and define that the result of `expression` becomes the input for `validateProfileId` or `minimumId`.
