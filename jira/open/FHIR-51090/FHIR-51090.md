- **Resolution Description**: For $expand, $validate-code ValueSet

1. Deprecate the system-version parameter
2. Add default-system-version with the same definition as system-version
3. Update the documentation for both parameters to:

> Specifies a default code system version to use for the operation, IF the value set definition itself does not specify which code system version to use. The format is the same as a canonical URL: [system]|[version] - e.g. http://loinc.org|2.56.

ONLY for the description of ValueSet $validate-code - add this text:

Note that this not the same as systemVersion which contains the version as part of the request (the code system version for the code being validated).

An example of where systemVersion and default-system-version contain different values is when data were collected using version A of a code system (systemVersion) however the client requests that the server validate the code against a ValueSet using version B of the code system (default-system-version).
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Description**: The ValueSet/$expand and ValueSet/$validate-code operations have a system-version parameter for specifying the version of a code system used in the operation. They also both have a default-valueset-version parameter, which serves the same purpose but for value sets used in the operation. The default-valueset-version naming is a clearer indication of what is happening, so we propose to:

Add default-system-version, identical to system-version, and
Deprecate system-version

in both operations.

### 6. Michael Lawley - 2026-02-25

We have pre-adopted support for all the variations in our R4 implementation.
As a general principle, we preference the more modern variants, but also require that if multiple "equivalent" (renamed) parameters are supplied that they have the same value - there is no "overriding" if the parameters are semantically equivalent.

I would prefer this hybrid rewording:

Specifies a default code system version to use for the operation, IF the value set definition itself does not specify which code system version to use. The format is the same as a canonical URL: [system]|[version] - e.g. http://loinc.org|2.56.
Note that this is a different parameter to systemVersion.

systemVersion is the version of the CodeSystem referenced in the system (IN) parameter, as opposed to any of the CodeSystems referenced in the ValueSet itself (themselves, in the case of included ValueSets).

Ontoserver uses it as a default system version fallback if an explicit default system-version has not been specified.
