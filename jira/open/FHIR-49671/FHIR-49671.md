- **Description**: Several (existing, older, or communication related) codes systems have the concept of a private code. A private code is a code for which the code system indicates that it does not define the meaning and the field can be used by implementers as they wish.

An example of such code includes the DICOM 7.8 Private Data Elements.

They typically appear in codes that used in messages where the code system is implicit.

The FHIR specification should provide guidance on:

whether private codes can be expressed in FHIR and
if so, how.

There has been a discussion on this topic in #IG creation > supporting private codes in code system - FHIR Community - Zulip.

Options mentioned in discussion are:

Do not represent -> when topic is expressed in FHIR an appropriate system needs to be provided that scopes the private code.
Include the code without code system when meaning is not known.
Include the code as a normal code in the CodeSystem (might require an extension on code system to link a code to a range of code).

I propose that FHIR states that:

FHIR resources can use private codes from code systems that define them
Implementations SHOULD:

For CodeableConcepts:

add a more descriptive code whenever a private code is used .
include the original private code.

For Codings

add a more descriptive code whenever a private code is used .

Additionally, an extension should be defined on CodeSystem allowing expression that a range of codes has the same definition (preventing adding thousands of codes with the same definition).

### 4. Elliot Silver - 2026-07-07

Those handle the broad problem, although I think there is room for refinement.

I have a bit of a problem with FHIR-50922 since it implies that for these private codes there is one definition for each code. In practice, there are often multiple. Different organizations can define different uses for the same Unicode private code point. Different manufacturers can define different meanings for the same private DICOM tags. In both cases, additional context is needed by a receiver to know which definition applies to which use. (And, in both cases, a receiving system should expect that various received resources would use various definitions.) However, I suspect that CodeSystem.context }}potentially along with the {{implicitRules element (or an extension, below) on the resource containing the private code might provide sufficient clarity?

(DICOM tags are particularly interesting since each system adding a private tag to an image essentially uses the next unused code on that image. If the system is the one that creates the image, it can use the first private tag slot; if the system is a far downstream image archive or image rendering system, it takes the next available slot, which will depend on what upstream systems have added. A separate part of the image file identifies which codes belong to which vendors. This is a simplification, but should be sufficient to illustrate the point.)

Given that it is often needed to be able to identify where these private codes came from in order to understand their meaning, an extension on Coding to identify "private code owner" would be helpful.
