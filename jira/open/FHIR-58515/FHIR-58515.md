- **Description**: After:
Many observations need to be grouped together in some fashion to document critical relationships for interpretation of the observations. The methods to do so primarily are through DiagnosticReport using DiagnosticReport.result and Observation using Observation.component and Observation.hasMember. See the Diagnostics Module for specific guidance on the supported patterns; a brief summary is here for convenience only.
It would be nice to have a short summary of the two patterns.

Something along the line of:
Pattern #1: The entire diagnostic report (as created by the fulfiller of the order(s)) is represented by a bundle containing one DiagnosticReport resource for the patient for a particular point in time. Some concepts, such as panels, are always represented as Observations, where Observation.code equals the panel code, and Observation.organizer is true.
and
Pattern #2: The entire diagnostic report (as created by the fulfiller of the order(s)) is represented by a bundle containing one or more DiagnosticReport resource instance(s). The DiagnosticReport resource represents a group of tests (e.g. a panel) usually performed together.
