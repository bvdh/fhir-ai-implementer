- **Resolution Description**: Clarify that:

When the percentage is expressed as a decimal, it shall be the decimal representation of a percentage (i.e. 0.3 = 30%)

Update the invariant for decimal values to be between 0 and 1, inclusive
Update the invariant for quantity values to be between 0 and 100, inclusive

Update all examples to make sure they follow these invariants, and consider adding the invariant that if a unit is present it shall be %
- **Change Category**: Clarification
- **Change Impact**: Compatible, substantive
- **Description**: It is unclear how percentages should be inputted within the prediction.probability[x]

Although we are using R4, for future-proofing against R6 I expect that:

probabilityQuantity is the probability between 0-100. e.g. a value of 30 equates to 30%

probabilityDecimal is the probability between 0-1 e.g. a value of 0.3 equates to 30%

The issue is the lack of guidance and the ambiguous examples:

all examples with a probability has a value <1 ,e.g. https://build.fhir.org/riskassessment-example-cardiac.xml.html , suggesting probabilityQuantity is between 0-1 which is contrary to `ras-3` `Probability as a Quantity must be <= 100%`
`ras-2` `Probability as a decimal must be <= 100` suggests that percentages are actually between 0-100 (e.g. 30 = 30%) which is contrary to how it is usually written in mathematics (between 0-1).

Suggestion
Guidance and examples indicate that:

probabilityQuantity is the probability between 0-100. e.g. a value of 30 equates to 30%

probabilityDecimal is the probability between 0-1 e.g. a value of 0.3 equates to 30%
ras-2 defined as `Probability as a decimal must be >=0 ,<= 1`
