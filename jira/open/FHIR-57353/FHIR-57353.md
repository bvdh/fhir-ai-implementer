NEW element BodyStructure.morphology

Element Id
BodyStructure.morphology

Definition
A single morphologic entity that spans multiple anatomical entries in the included structures.

Short Display
Morphology of the body structure

Cardinality
0..1

Terminology Binding
SNOMED CT Morphologic Abnormalities (Example)

Type
CodeableConcept

Summary
true

Comment
Use this element when a morphology applies to the overall body structure or spans multiple structures and cannot be attributed to a single included structure. Morphologies specific to an individual included or excluded structure should be represented using BodyStructure.includedStructure.morphology or BodyStructure.excludedStructure.morphology.

Revisions to BodyStructure.includedStructure.morphology

Element Id
BodyStructure.includedStructure.morphology

Definition
The morphology of the included anatomical or pathological structure. This can define both normal and abnormal morphologies.

Short Display
Structure morphology

Cardinality
0..*

Terminology Binding
SNOMED CT Morphologic Abnormalities (Example)

Type
CodeableConcept

Summary
true

Comments
The minimum cardinality of 0 supports the use case of specifying a location without defining a morphology. When multiple morphologic characteristics apply to the same body structure, a single pre-coordinated terminology concept or post-coordinated expression may be used when an appropriate representation exists. Multiple repetitions of morphology can be used to represent individual morphologic characteristics when no suitable single concept or expression is available.

Changes to BodyStructure.excludedStructure

Definition
The anatomical location(s) or region(s) not occupied or represented by the body structure, morphologic entity, or specimen.

### 4. John D.L. Nolen - 2026-09-11

*Proposed disposition:*

Add a *Spanning Morphology* element to BodyStructure to represent a morphologic entity whose definition encompasses multiple anatomical structures. Remove references to “normal” morphology from the definitions and comments of the `.morphology` elements.

*Proposed definition:*

> *Spanning Morphology:* A morphologic entity that encompasses or involves multiple anatomical structures and whose morphology applies to the structures collectively rather than independently to each structure.

The proposed changes are:

1. Add `BodyStructure.spanningMorphology`, with a reference to the applicable morphology terminology.
2. Define `BodyStructure.spanningMorphology` as describing the morphology of the BodyStructure as a whole, rather than the morphology of an individual anatomical structure.
3. Retain `BodyStructure.includedStructure.morphology` for morphology that applies specifically to an individual included anatomical structure.
4. Remove references to “normal” morphology from the definitions and comments of the `.morphology` elements.
5. Add guidance distinguishing the two:

Use `spanningMorphology` when a single morphologic entity encompasses multiple anatomical structures.
Use `includedStructure.morphology` when morphology is specific to an individual included structure.
Do not repeat a spanning morphology on each `includedStructure` solely because those structures participate in the spanning morphology.

For example:

```text
BodyStructure
spanningMorphology = X
includedStructure
structure = A
includedStructure
structure = B
includedStructure
structure = C
```

This allows the model to represent morphology that spans multiple anatomical structures without duplicating the same morphology on each structure, while preserving structure-level morphology for cases where it is independently applicable.

Use *Spanning Morphology* rather than introducing a separate `MorphologicGroup` entity. The spanning morphology is itself the clinically meaningful entity, with the included structures identifying its anatomical extent.

### 11. David Barwin - 2026-07-10

Some idea generation on what a potential profile could be:
BodyStructure Longitudinal Tracking Profile

This profile supports longitudinal tracking of anatomical and pathological structures by constraining each BodyStructure to represent a single includedStructure and by defining explicit relationships between BodyStructure resources.
Constraints

Element
Constraint

BodyStructure.includedStructure
Cardinality constrained to 1..1. Each BodyStructure SHALL represent a single anatomical or pathological structure.

BodyStructure.extension:relationship
Optional, repeating extension used to relate this BodyStructure to other BodyStructure resources.

Relationship Extension

Context

BodyStructure

Cardinality

0..*

Extension Definition

Element
Cardinality
Type
Description

extension:type
1..1
CodeableConcept
The nature of the relationship to the referenced BodyStructure (e.g., predecessor, successor, part-of, includes, equivalent-to, split-from, merged-from).

extension:target
1..1
Reference(BodyStructure)
The related BodyStructure.

The relationship is interpreted from the perspective of the current BodyStructure.
Guidance

Longitudinal tracking requires a stable identity for each tracked anatomical or pathological structure. By constraining BodyStructure to contain exactly one includedStructure, the existing BodyStructure.identifier serves as the persistent business identifier for that structure. Relationships between tracked structures, such as predecessor, split-from, merged-from, part-of, or includes, can then be represented explicitly through the relationship extension without introducing additional identifiers or changing the core BodyStructure model. This approach preserves interoperability with the base resource while providing a standardized mechanism for expressing structural and temporal relationships between tracked entities.
