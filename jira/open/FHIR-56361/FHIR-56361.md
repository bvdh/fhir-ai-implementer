- **Description**: Pupillary distance is usually part of a vision prescription, but there is no place for it today in the VP resource.

The proposal is to:
1. Create a top level `monocularPD` backbone element (0..1), like so:
```
binocularPD:
{
near: decimal // Near binocular pupillary distance, in millimeters
far: decimal // Far binocular pupillary distance, in millimeters
}
```
2. Create a similar backbone element `monocularPD`, (0..1), within `lensSpecification`, like so:
```
monocularPD:
{
near: decimal // Near monocular pupillary distance, in millimeters
far: decimal // Far monocular pupillary distance, in millimeters
}
```
3. Create an invariant that if monocularPD for both left & right eye are present, there should NOT be a binocularPD of the same quality ("near" vs. "far") or require the math to add up (probably less preferred).

### 12. Marti Velezis - 2026-05-11

Adding comment from SME - Andreas Gonzalez (via CCOI/Eyes on FHIR)

"Short answer: yes - I'd support adding Mono PD, Distance PD, and Near PD to VisionPrescription.

In traditional in-person dispensing, PD isn't really a prescribing parameter - it's a dispensing parameter. The optician at the optical always measures it directly when fitting the patient, every time, without exception. That's the reason vision prescriptions historically leave the field unpopulated: from the prescriber's side, PD wasn't theirs to capture. The optician owned it.

What's changed is direct-to-consumer eyewear and patient-mediated record exchange. Warby Parker, Zenni, EyeBuyDirect, and the broader patient-app ecosystem all assume the patient can hand over a complete, fillable prescription without an optician in the loop. In that pathway, PD has to travel with the Rx. In these cases, patients either request their prescription have their PD from the prescribing doctor, or they guess from a ruler at home.

So the case for populating Mono PD, Distance PD, and Near PD in VisionPrescription is really a case for supporting the DTC and patient-mediated workflows that the in-person-optician model never had to worry about. Near PD in particular isn't derivable from Distance PD with sufficient accuracy for progressives (convergence reduces it by 3-4 mm), so it has to be carried separately."
