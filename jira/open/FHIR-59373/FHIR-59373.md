# FHIR-59373: Validation warning for extensible bindings does not represent the definition of extensible

- **Request in-person**: Rick Geimer
- **Description**: When validating extensible bindings with a code outside the value set, I get a warning (expected) but the text is incorrect. The warning text for Encounter.class was this:

The Coding provided (http://example.org/fakecs#blah) was not found in the value set 'V3 Value SetActEncounterCode' (http://terminology.hl7.org/ValueSet/v3-ActEncounterCode|2014-03-26), and a code should come from this value set unless it has no suitable code (note that the validator cannot judge what is suitable).

This issue is with the word "should" above, which I highlighted. The actual text for extensible says the following:

To be conformant, codes in this element SHALL be from the specified value set if any of the codes within the value set can apply to the concept being communicated.

The current warning leads implementers to think conforming to extensible bindings is a "nice to have" instead of a requirement. I understand this cannot be made an error, but the warning message should at least accurately reflect the definition.
