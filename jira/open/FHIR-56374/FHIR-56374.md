Proposed fully revised text reads as follows:

The PractitionerRole resource describes the types of services that practitioners provide for an organization at specific location(s). PractitionerRole can be used in multiple contexts including:

Provider Registries where it indicates what a practitioner can perform for an organization (may indicate multiple healthcareservices, locations, and roles)
In a Clinical system where it indicates the role, healthcareservice and location details associated with a practitioner that are applicable to the healthcare event (e.g. Observation, Appointment, Condition, CarePlan)
In a Clinical system as a point of reference rather than an event, such as a patient's preferred general practitioner (at a specific clinic)

The code, specialty, location, telecom, healthcareService, and other properties can be repeated if required in other instances of the PractitionerRole. Some systems record a collection of service values for a single location, others record a single service and the list of locations it is available. Both are acceptable options for representing this data.

Implementations should create a separate PractitionerRole instance when repeated properties are not valid across all other content in an instance. For example, where all the healthcareServices referenced in an instance are not available at all locations referenced by that instance. To prevent instances where properties are not valid across all other properties in the resource, some implementations profile the cardinality of repeated elements in PractitionerRole to include only a single value.

Many resource types have a choice of a reference to either a Practitioner resource or a PractitionerRole resource. The latter provides organizational context for the practitioner's participation when it is required, otherwise a direct reference to the practitioner may be used.

References to PractitionerRole from other resources sometimes describe a specific context or type of role. For example, Patient.generalPractitioner implies a role of General Practitioner. Likewise, Appointment.participant (through the .type property) defines roles such as admitter, discharger, translator, etc. Implementations can use practitionerRole.code to express these roles as well; having duplicate values across the resources is not a concern (and can be used for discovery). Other examples include CarePlan.contributor, Immunization.informationSource, and Immunization.performer (through the .function property).

For use cases where an organization has activities where a practitioner is not defined/pre-allocated for a specific role (e.g. an un-named surgeon at XYZ Hospital), a PractitionerRole resource can be used with an empty Practitioner property, and the other relevant role properties populated - i.e. code, organization.
