- **Description**: Bundle, Binary and Parameters resources don't allow extensions. This has been problematic in at least two cases:

I've personally had useful metadata I wanted to include in Bundle.
The Bulk Data IG uses the Parameters resource for Bulk Import, and we had to use janky workarounds to allow child IGs to add their own metadata.

FHIR defines a super useful, consistent way to extend FHIR resources (extensions). We should allow that feature to be used on all the FHIR resources, including Bundle and Parameters. And Binary while we are at it.

### 3. Cooper Thompson - 2026-07-21

There are two uses cases I've personally run into:

I've wanted to put metadata on Bundle summarizing the contained content. You can see what I ended up doing here: https://open.epic.com/Endpoints/Brands. But basically I put the info in an extension in Bundle.identifier. This of course makes no sense semantically, but it at least doesn't fail validation. When I get a chance, I'll likely move it to Bundle.meta, as that is a better option.
Bulk Data IG was considering how to let child IGs add their own metadata to the manifest (Parameters). We ultimately pivoted to a logical model instead of a Parameters profile, so that is non-issue now.

So for my primary, outstanding use case, Bundle.meta works.

So perhaps the outcome of this ticket can change from "add extensions to Bundle/Parameteres/etc." and instead "explain how .meta.extension is different from extensions in general, because now that I'm thinking about .meta, it isn't clear to me when you would use one vs. the other. (specifically, Resource.meta.extension vs. Resource.extension)

And for future readers, it might also be interesting to explain why .extension isn't on Bundle, Binary, and Parameters. I still don't really know why. I can kinda understand Binary (because it's default rendering is the content not the resource), but not having it on Bundle and Parameters seems really odd.
