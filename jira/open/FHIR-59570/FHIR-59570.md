# FHIR-59570: Dosage condition codes: remove the duplicate code, fix the value set metadata, and move the code system and value set to THO

- **Summary**: Dosage condition codes: remove the duplicate code, fix the value set metadata, and move the code system and value set to THO

- **Resolved**: 2026-10-08
- **Status**: Triaged
- **Project**: FHIR Specification Feedback

- **Related Page(s)**: Dosage
- **Resolution Description**: Remove tolerates; keep medication-tolerated (consistent with medication-funded and medication-available). Since the code system is new in R6, the code can be removed rather than deprecated.
Fix the dosage-condition-code value set: name DosageConditionCodes, title "Dosage Condition Codes", description "Codes for the conditions under which a dosage applies (for example, if needed, if tolerated, if a problem abates)".
Correct the source URLs: http://hl7.org/fhir/ValueSet/dosage-condition-code and http://hl7.org/fhir/ValueSet/dosage-condition-details.
Set publisher and contact of both value sets to the Pharmacy work group.
Apply the text corrections above, including: "For these codes, DosageCondition.value[x] is boolean: true (or absent) means the condition holds; false means it does not." and full definitions for medication-tolerated, medication-funded and medication-available.
Submit a UTG proposal to move the code system dosage-condition-code and the value set dosage-condition-code to THO (with the corrections above); once approved, bind DosageCondition.code to the THO value set and remove the core copies. The value set dosage-condition-details stays in core as an example.
- **Change Category**: Clarification
- **Change Impact**: Non-compatible
- **Description**: The code system http://hl7.org/fhir/CodeSystem/dosage-condition-code (bound with preferred strength to DosageCondition.code) and its value sets are new in R6 (since 6.0.0-ballot4). Several corrections are needed before publication.

Duplicate code. tolerates ("Patient tolerates Medication" – "Whether the patient tolerates a medication (e.g. SCT 1303423003)") and medication-tolerated ("Medication Tolerated" – "Medication Is Tolerated") have the same meaning and the same properties (type boolean; details: "Can nominate another medication that this depends on …"). Implementers have to choose arbitrarily between them.
Wrong value set metadata. The value set http://hl7.org/fhir/ValueSet/dosage-condition-code is published with name DoseLimitScopeVS, title "Dose Limit Scope ValueSet" and description "Additional Binding Purpose" – apparently copied from another value set.
Source URLs. In the source, both valueset-dosage-condition-code.xml and valueset-dosage-condition-details.xml have the URL http://hl7.org/fhir/tools/ValueSet/dosage-condition-code (a tools URL, and the same URL for two value sets). The build publishes them under http://hl7.org/fhir/ValueSet/…, but the source should be correct.
Publisher. Both value sets say "HL7 International / FHIR Infrastructure" with the FHIR-I contact, while the owning work group is Pharmacy.
Text corrections.

problem-abates, problem-presents: "a symptom, problem of finding" → "a symptom, problem or finding".
Property type: "The type that goes in ConditionDetails.value for this code" → "… in DosageCondition.value[x] for this code".
The meaning of the value is not stated: all codes have type boolean, but it is not said that value[x] = true means the condition holds (for example, the medication is tolerated) and false that it does not, nor what an absent value means.
medication-tolerated, medication-funded, medication-available: definitions are only restated titles ("Medication Is Tolerated"); give full definitions.

Move to THO. The code system is fit for production use (status active, experimental = false, preferred binding, normative) and can be used by other specifications and implementation guides, which may bind it more tightly. It should therefore be maintained in THO, together with the value set dosage-condition-code. The value set dosage-condition-details (example binding, a few SNOMED CT concepts, experimental = true) is illustrative and can stay in core.
