- **Description**: No documentation on how to process the "params" parameters.

specifically how to "URL encode" complex parameters like coding, codeableconcept, codesystem (if there's another part of the fhir spec that provides this detail, add a reference to it)
if not all parameters are able to be supported, indicate which ones are explicitly supported.
The %factory functions take multiple parameters and use {} to skip ones not used (inconsistency)

Include examples for each function call showing a use case where it would be sensibly used

%terminology.subsumes should indicate what benefits it provides over using the fluent subsumes or subsumedBy functions, if it is just to be able to provide additional parameters, why not add those parameters and remove this function altogether.

Should have guidance on what should happen if a terminology server is not available (added a seperate ticket FHIR-53953 for general remove services)
