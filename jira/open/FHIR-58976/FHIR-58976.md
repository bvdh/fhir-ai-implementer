- **Description**: Affected element:

`TestScript.variable.defaultValue`

In R5, `variable.defaultValue` is defined as:

> A default, hard-coded, or user-defined value for this variable.

The comments additionally describe the element as a predefined value that can be used as either a default or an override. Test engines may optionally use it as a placeholder for a user-defined execution-time value.

These are different semantics represented by a single element:

a fixed or hard-coded value that the engine must use unchanged;
a default value that may be replaced by a user or execution environment;
an override value that takes precedence over another variable source.

A test engine cannot determine from `defaultValue` which interpretation the author intended. In particular, it cannot determine whether the value should be presented for configuration or must remain unchanged.

As a result, TestScript authors are adding instructions such as “do not change this value in the UI” to `variable.description` or `variable.hint`.

Introduce separate machine-readable representations for:

a fixed value that cannot be replaced by execution-time input; and
a default value that may be replaced by a user or execution environment.

For example, `fixedValue` could represent the first case while `defaultValue` retains the second.
