- **Resolution Description**: In $care-gaps, $evaluate, and $collect-data, change the parameter names from 'reporter' and 'reporterResource' to 'provider' and 'providerResource'.

In $care-gaps and $evaluate, the below are the desired descriptions:

for 'provider':

The provider for which the report will be run. This may be a reference to a Practitioner, PractitionerRole, or Organization. If specified, systems MAY use this information to determine subjects for which the measure will be calculated, but how subjects are determined is implementation-specific. This parameter is reflected in the reporter element of the resulting MeasureReport(s). This parameter cannot be used with the providerResource parameter.

for 'providerResource':

The provider for which the report will be run, provided as a Practitioner, PractitionerRole, or Organization resource. This is intended to support the use case in which the organization information is not on the server performing the evaluation, for example an ad-hoc group of practitioners that are part of a provider group. This parameter is reflected in the reporter element of the resulting MeasureReport(s). This parameter cannot be used with the provider parameter.

In $collect-data, the below are the desired descriptions:

for 'provider':

The provider for which the data-of-interest will be collected. This may be a reference to a Practitioner, PractitionerRole, or Organization. If specified, systems MAY use this information to determine subjects for which the data-of-interest will be calculated, but how subjects are determined is implementation-specific. This parameter is reflected in the reporter element of the resulting MeasureReport(s). This parameter cannot be used with the providerResource parameter.

for 'providerResource' (this is the same as the description above in $evaluate and $collect-data):

The provider for which the report will be run, provided as a Practitioner, PractitionerRole, or Organization resource. This is intended to support the use case in which the organization information is not on the server performing the evaluation, for example an ad-hoc group of practitioners that are part of a provider group. This parameter is reflected in the reporter element of the resulting MeasureReport(s). This parameter cannot be used with the provider parameter.

In $care-gaps, remove the 'practitioner' parameter.

In $care-gaps, the definitions of the isDocument and return parameters incorrectly describe the result bundles. They should be updated as well to:

isDocument:

The isDocument parameter controls whether a Gaps in Care Composition is returned in the Bundle (i.e. if the Bundle is of type `document`). When 'true' the returned Bundles contain the Gaps in Care Composition. This parameter defaults to 'true'.

return:

The $care-gaps operation returns zero or more Bundles, one for each input
subject. If `isDocument` is true, each bundle SHALL have a `type` of `document` and SHALL contain a Composition to define a document consisting of one or more MeasureReports as well as related gaps-in-care resources (GuidanceResponse and DetectedIssue). If `isDocument` is false, each bundle SHALL have a type of `collection`, SHALL contain at least the MeasureReport(s) and SHOULD contain the resources used to calculate the measure report. In addition, the collection bundle MAY contain the gaps-in-care-specific resources describing the gaps.\n\nNote that even though there is a single parameter named return of type Bundle, it is a multi-cardinality parameter, and so will still be returned using a Parameters resource, as described in the general operations framework [response](operations.html#response).

- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Description**: The parameters to the $care-gaps, $evaluate, and $collect-data operations were updated to add reporter and reporterResource as a result of implementation experience in the Data Exchange for Quality Measures implementation guide, where those parameters were aligned across the operations and generalized to support generically specifying what provider the report is being run for.

However, the name "reporter" is not as clear as it could be, and we propose to change the parameter names from reporter and reporterResource to provider and providerResource in all 3 operations ($care-gaps, $evaluate, $collect-data)

In addition, part of applying this change to the $care-gaps operation was supposed to have removed the practitioner parameter, that was the point of the change was that it was generalizing multiple specific parameters into a single parameter. Other parameters were removed, but the practitioner one was not, so we should complete that change as part of this and remove the practitioner parameter from the $care-gaps operation.

As well, add a clarification to the provider and providerResource parameters that the resolved provider will appear in MeasureReport.reporter, and that this is not typically the same as the reportingVendor.

### 1. Bryn Rhodes - 2026-08-11

Note also that the definitions of the isDocument and return parameters incorrectly describe the result bundles. They should be updated as well to:

isDocument:

The isDocument parameter controls whether a Gaps in Care Composition is returned in the Bundle (i.e. if the Bundle is of type `document`). When 'true' the returned Bundles contain the Gaps in Care Composition. This parameter defaults to 'true'.

return:

The $care-gaps operation returns zero or more Bundles, one for each input
subject. If `isDocument` is true, each bundle *SHALL* have a `type` of `document` and *SHALL* contain a Composition to define a document consisting of one or more MeasureReports as well as related gaps-in-care resources (GuidanceResponse and DetectedIssue). If `isDocument` is false, each bundle *SHALL* have a type of `collection`, *SHALL* contain at least the MeasureReport(s) and *SHOULD* contain the resources used to calculate the measure report. In addition, the collection bundle *MAY* contain the gaps-in-care-specific resources describing the gaps.\n\nNote that even though there is a single parameter named return of type Bundle, it is a multi-cardinality parameter, and so will still be returned using a Parameters resource, as described in the general operations framework [response](operations.html#response).
