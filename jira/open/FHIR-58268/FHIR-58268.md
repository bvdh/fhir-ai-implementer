- **Description**: Much of this entire section (and sub-sections) is broadly applicable and is not limited to the FHIR R6 specification. As such the majority of this content should be removed from this specification.

Standards Development Process - should be in a separate document independent of this FHIR standard. As is stated: "This section describes how HL7 develops a standard..." - no specific to this FHIR specification.
FHIR Maturity Model - should be in a separate governance-type document. It is also applicable to other FHIR specifications.
FHIR releases and versioning - this should be in a separate governance-type document. It is also applicable to other FHIR specifications (IGs and THO?).
version identification - can remain
Rules for inter-version change - should be a separate document that is applicable to all HL7 specifications, including FHIR IGs and non-FHIR specifications alike.
Managing change during development process - should be removed
Extensions for converting between versions - can remain
Plans for future releases - should be removed completely
