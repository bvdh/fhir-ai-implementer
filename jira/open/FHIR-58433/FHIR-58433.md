- **Description**: Currently, the TerminologyCapabilities resource allows assertions of the extent of the content of the code system (the concepts and codes it defines) via the TerminologyCapabilities.codeSystem.content element. However, given that there is not a similar element under TerminologyCapabilities.codeSystem.version it is not possible for differences between versions to be asserted e.g. if the servers supports versions 1 as complete, and version 2 as a fragment, this cannot be asserted.

One of the following two approaches as recommended:

Approach 1

Add TerminologyCapabilities.codeSystem.version.content as an optional element to assert the content of that particular version of the code system.
Retain TerminologyCapabilities.codeSystem.content but refine it to mean that it applies to all versions of the code system that do not have a TerminologyCapabilities.codeSystem.version.content value. Further, add a note to indicate that for a particular code system version, the TerminologyCapabilities.codeSystem.version.content element value has precedence.
Add a constraint which says that for every TerminologyCapabilities.codeSystem ** element, there SHALL either be a TerminologyCapabilities.codeSystem.content element, or each TerminologyCapabilities.codeSystem.version element SHALL have a content subelement.

Approach 2

Add TerminologyCapabilities.codeSystem.version.content as a mandatory element to assert the content of that particular version of the code system.
Remove the TerminologyCapabilities.codeSystem.content element
