- **Description**: TestScript.*.action.assert.navigationLinks is a boolean indicating whether the engine performs validation on Bundle navigation links. Its comments state that the assertion checks for first, last and next links.

The specification does not define what this validation entails. It is unclear whether the engine only checks that these links are present, validates their URL values or applies additional rules concerning Bundle pagination.

It is also unclear when each link is expected. For example, how should an engine determine whether a last link must be present for a particular search result? The assertion contains no information about the expected paging behavior or the position of the returned Bundle within the result set.

If validation only means checking that first, last and next links are present, the element adds little value over an explicit expression assertion. It is also less flexible because:

it does not allow an author to select which navigation relations are expected;
it cannot validate the value of a navigation URL;
it cannot accommodate different expectations for different pages of a result set.

These expectations can already be represented explicitly using separate assertions with the existing FHIRPath-based expression element. For example:

"expression": "Bundle.link.where(relation = 'first').url.exists()"

"expression": "Bundle.link.where(relation = 'last').url.exists()"

"expression": "Bundle.link.where(relation = 'next').url.exists()"

Authors can adjust these expressions for the navigation relations and conditions relevant to a particular FHIR search response. Using separate assertions also produces a distinct result for each expectation.

A leaner and less ambiguous specification should prefer the existing general assertion mechanism over a boolean shorthand whose validation behavior is not defined.

Could TestScript.*.action.assert.navigationLinks be deprecated in favor of one or more assertions using expression? If the shorthand is retained, could the specification define what validation entails and when each navigation relation is expected?
