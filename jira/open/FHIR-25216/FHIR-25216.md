- **Description**: https://build.fhir.org/fhirpath.html#types indicates that FHIRPath evaluation engine will "automatically convert the value of FHIR types representing primitives to FHIRPath types when they are used in expressions".

However, https://build.fhir.org/fhirpath.html#quantity indicates that "The Mapping from FHIR Quantity to FHIRPath System.Quantity can only be applied if the FHIR Quantity has a UCUM code - i.e. a system of [http://unitsofmeasure.org,|] and a code is present."

This begs the question "what if a quantity is used in an expression and cannot be mapped to a FHIRPath quantity?"

This is not just hypothetical because we have constrains like rng-2 "low.empty() or high.empty() or (low <= high)" which compare two quantities.

I think it would be good for https://build.fhir.org/fhirpath.html#quantity to clarify that two FHIR.Quantity objects are comparable in FHIRPath if (and only if?) they have the same system and code (coded unit).The case where both are UCUM is already covered by auto-converting to System.Quantity types and comparing as described in FHIRPath.However if they have non-UCUM units, we should clarify that they can still be evaluated in certain cases.

Question: which FHIRPath functions and operations can be performed over FHIR Quantities?* Equality? probably yes* Comparison? probably yes* Math? probably not since we cannot compute the resulting unit

## Comments

### 1. Lloyd McKenzie - 2026-04-20

We don't believe this issue is FHIR-specific.

Proposed disposition:
"FHIR.Quantity objects are comparable if:

They have the same system and code (coded unit),
They have a code system of "http://unitsofmeasure.org" and UCUM defines the units as comparable, or
There is a ConceptMap available to the engine that allows 'exact' conversion of the unit code present to a UCUM code and the mapped-to UCUM codes are comparable."

### 2. Brian Postlethwaite - 2026-04-02

We could add defintions/overloads for what fhir quantity comparison looks like with FHIR types (as we do for equality, ofType() and toString())

Math addition/subtraction could be done, and possibly multiplication when one of them is the special ucum default unit '1' (as that doesn't change the unit).
