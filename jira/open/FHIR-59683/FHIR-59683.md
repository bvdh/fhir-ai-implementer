- **Description**: ServiceRequest.orderDetail.parameter.value[x] allows Quantity, Ratio, Range, boolean, CodeableConcept, string and Period. There is no way to carry a clock time or an instant as a structured parameter value.

Use case: nursing procedure orders specify several administrations per day at fixed times, each with its own amount, e.g. 08:00 twice, 12:00 once, 16:00 twice. occurrenceTiming.repeat.timeOfDay holds the times but cannot pair each time with its amount. orderDetail can group a time and an amount in one entry, but the time has to be sent as valueString "08:00", which is not computable. valuePeriod does not help because Period.start is a dateTime and requires a date.

Encountered in the Uzbekistan Digital Health Platform nursing component, where each slot is one orderDetail with parameter.code SNOMED CT 442371002 "Start time of procedure" plus 252109000 "Number of times".

Proposed change: add time and dateTime to the value[x] choice on ServiceRequest.orderDetail.parameter.value[x], matching the choice already available on Observation.component.value[x].

Related: FHIR-32265 introduced the parameter structure. FHIR-54622 (not persuasive) confirmed the structure stays, so extending its value types is the remaining route.
