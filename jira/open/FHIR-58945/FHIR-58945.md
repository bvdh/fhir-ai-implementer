# FHIR-58945: Clarify applicabilityBehavior in the case of unknown applicability

- **Related Artifact(s)**: PlanDefinition
- **Resolution Description**: Agreed, clarify that when applicabilityBehavior is Any and the result of evaluating an applicability condition on a child action is "null" (i.e. applicability is unknown), the processing should stop (rather than assuming the applicability is false and continuing on with processing).

Add an "action.applicability" to RequestOrchestration to capture the result of evaluating the applicability criteria of the action. 0..1 boolean, and document that data-absent-reason with a value of "unknown" is used to capture that the result of the applicability criteria was null.

Update the PlanDefinition realization documentation to document this behavior.
- **Resolution Vote**: Brenin Rhodes/Chris Schuler: 9-0-0
- **Vote Date**: 2026-09-09
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: In the case that applicabilityBehavior is Any and the applicability criteria of a child action returns "null" (i.e. the applicability is unknown), the processing should stop (rather than treating it as false and continuing to process the next sibling action).

In addition, add to the RequestOrchestration the ability to represent the actual result of the applicability criteria, true/false/unknown (use data-absent-reason)
