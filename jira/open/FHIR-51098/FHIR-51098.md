# FHIR-51098: Add a new element for the canoncaization algorithm to Signature

- **Summary**: Add a new element for the canoncaization algorithm to Signature
- **Created**: 2025-06-13

- **Status**: Waiting for Input
- **Project**: FHIR Specification Feedback

- **Resolution**: Persuasive
- **Specification**: FHIR Core (FHIR)

- **Work Group**: FHIR Infrastructure
- **Related Artifact(s)**: Bundle
- **Related Page(s)**: Datatypes
- **Resolution Description**: 1. Will add a new 0..1 canonicalizationAlgorithm with type uri.

Definition: "A reference to the formal canonicalization algorithm used with this signature."

However: looks redundant with the mechanism to send canonicalization as part of the mime type. Grahame to investigate
- **Change Category**: Enhancement
- **Change Impact**: Non-substantive
- **Description**: When creating a signature on a resource- typically, a Bundle - the resource has to be canonicalized as part of the signature process. The standard defines several different values for how a resource was canonicalised that have to do with the scope of what's being signed

The canonicalisation method has to be written into the JWS header, if you're doing sigFormat = application/Jose, and it needs to be there - it needs to be signed

But it's an interesting thing to know even if you're not verifying the signature - what's the scope of the signature. The best way is to add an element for this to Signature

See Signature on Zulip
