- **Resolution Description**: For specimen reject reason (or any other cancellation reason) need to cover several scenarios:

Not part of the reject reason discussion, but here for completeness - testing was completed:

Task

.status = complete

.businessStatus = complete

.statusReason = empty

.output[1].type = code for "diagnostic report"

.output[1].valueReference = reference to DiagnosticReport, with all the referenced resources

Testing was partially completed:

Task

.status = complete

.businessStatus = partly completed

.statusReason = code for "specimen related"

.output[1].type = code for diagnostic report

.output[1].valueReference = reference to DiagnosticReport, with all the referenced resources, where the Observations that could not be completed have.dataAbsentReason

Optionally can include:

.output[2].type = code for "Relevant Finding"

.output[2].valueReference = reference to Observation stating "Specimen is hemolyzed" and pointing from this Observation to the Specimen 1

Test request was canceled:

Task

.status = canceled

.businessStatus = <whatever is appropriate for the domain>

.statusReason = code for "specimen reject"

.output[1].type = code for "Relevant Finding"

.output[1].value = reference to Observation stating "Specimen is hemolyzed" and pointing from this Observation to the Specimen 1

.output[2].type = code for "Recommendation"

.output[2].valueReference = reference to any resource that can communicate a recommendation (Communication / Observation / Task / ServiceRequest / DeviceRequest)
- **Request in-person**: Hans Buitendijk
- **Description**: When a specimen, image, or other test is cancelled or changed the reasons for cancelled, the reason for that action can vary by kinds of test (e.g., reasons related to the specimen, or images) or other reasons that are not well suited to add to the higher-level status reason codes (ServiceRequest.statusReason, Task.statusReason, and Observation.dataAbsentReason or Observation.statusReason).

The suggestion is to add a general purpose attribute (preferred for Observation, but may be an extension for the others or a common extension for all) that captures a value using CodeableConcept plus a note, and potentially a type to clarify the relevant binding to various codesystems/valuesets that may be appropriate for the kind of test and context.
