- **Resolution Description**: We will:

We will create a page in the api incubator IG called "Managing additional resources".
We will add a section to that incubator page called "References to additional resources" that talks about the additional-resource-target extension. We will reference that section from the 'references' page in the section dealing with additional resources.
Create a new 0..* extension called additional-operation-context extension with context Resource and type canonical - canonical URL of the operation whose context (i.e. OperationDefinition.resource) is being supplemented to include this resource
Create a new 0..* complex extension called additional-operation-parameter-allowedType extension with context Resource
url: canonical 1..1 - Canonical URL of the operation whose parameter this resource should be permitted as an additional type for.
name: code 1..1 - Parameter name with a type of Resource that this additional resource is to be considered an additional permitted allowedType for.
use: code 1..1 - The 'use' value that corresponds to the parameter being supplemented
Create a new 0..* complex extension called additional-operation-parameter-targetProfile extension with context Resource
url: canonical 1..1 - Canonical URL of the operation whose parameter this resource should be permitted as an additional type for.
name: code 1..1 - Parameter name with a type of Resource that this additional resource is to be considered an additional permitted targetProfile for.
use: code 1..1 - The 'use' value that corresponds to the parameter being supplemented
In the new api incubator page, add a section called "Additional resources with operations" and refer to the three operation-related extensions defined above and indicate how they're used. We will update the OperationDefinition notes section to add a section called "Using operations with additional resources" that refers to the new api page section.
Update the 'additional resources' section on Resource to point to the new section in OperationDefinition

- **Description**: It is recommended that the support for Additional Resources in OperationDefinition be clarified in the resource type's description. Currently, it seems as though:

The types in which an operation can be executed (OperationDefinition.resource element) does not appear to support additional resources given the binding.
The types support for an operation parameter (OperationDefinition.parameter.type element) does not appear to support additional resources given the binding.

Whether or not the above are intentional, it would be helpful to clarify if (and how) additional resources are supported by OperationDefinition instances.
