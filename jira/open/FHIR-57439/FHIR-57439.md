# FHIR-57439: Clarify and correct PackagedProductDefinition search parameters for contained item references

## Metadata

- **Summary**: Clarify and correct PackagedProductDefinition search parameters for contained item references
- **Created**: 2026-05-25
- **Updated**: 2026-08-04
- **Resolved**: 2026-08-04
- **Status**: Triaged
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Joao Almeida
- **Resolution**: Persuasive with Modification
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: Biomedical Research & Regulation
- **Related Artifact(s)**: PackagedProductDefinition
- **Resolution Description**: Retain the resource-specific search parameters, but constrain their targets and descriptions consistently:

biological → target only BiologicallyDerivedProduct
device → target only DeviceDefinition
manufactured-item → target only ManufacturedItemDefinition
nutrition → target only NutritionProduct
package → target only PackagedProductDefinition
- **Change Category**: Enhancement
- **Change Impact**: Non-compatible
- **Applied for Version**: R6
- **Description**: The current PackagedProductDefinition search parameters appear to define several resource-specific parameters — biological, device, manufactured-item, medication, nutrition, and package — but all use the same expression:

PackagedProductDefinition.repeat(packaging).containedItem.item.reference

In the detailed search parameter page, these parameters also appear to list the same target resources, regardless of the parameter name. For example, device, nutrition, biological, manufactured-item, and package all resolve against the same expression and broad target set. This makes the parameters semantically indistinct.

Suggested change:

Either:

Keep only a generic contained-item search parameter for:

PackagedProductDefinition.packaging.containedItem.item.reference

with all permitted target types.

Or:

Retain the resource-specific search parameters, but constrain their targets and descriptions consistently:

biological → target only BiologicallyDerivedProduct
device → target only DeviceDefinition
manufactured-item → target only ManufacturedItemDefinition
nutrition → target only NutritionProduct
package → target only PackagedProductDefinition

Also consider removing or renaming medication, since the contained item is not a Medication resource. The current description says “A manufactured item of medication”, but the actual allowed target is ManufacturedItemDefinition, not Medication.

### 3. Rik Smithies - 2026-07-24

These were all designed on purpose to make queries easier to read. There can only be one item present, never a mixture. So when you want a query that fetches the device you can use a query with that name, rather than just "item". It makes the intention of the search easier to understand (for api users).

But I agree that it would be helpful to make these named search parameters only target the specific types.

But I disagree about re-naming or removing the "medication" search parameter. That would be a breaking change.

In common language terms the MID resource is the medication within. It doesn't mean, and doesn't need to mean that it is a literally Medication resource. This parameter was given the name "medication" deliberately, so that users can easily find a way to get to the medication in the package, without having to use the less unfamiliar term "manufactured item" (and, as above, queries that are written, and documented, are then easier for users to understand).
