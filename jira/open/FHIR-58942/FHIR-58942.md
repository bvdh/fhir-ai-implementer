# FHIR-58942: RequestOrchestration needs location

## Metadata

- **Summary**: RequestOrchestration needs location
- **Created**: 2026-09-09
- **Updated**: 2026-09-23
- **Resolved**: 2026-09-16
- **Status**: Resolved - change required
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Lloyd McKenzie
- **Resolution**: Persuasive
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R5
- **Work Group**: Clinical Decision Support
- **Related Artifact(s)**: RequestOrchestration (was RequestGroup)
- **Resolution Description**: Agreed, add a location element to RequestOrchestration:

location 0..* CodeableReference(Location), bound example to http://terminology.hl7.org/ValueSet/v3-ServiceDeliveryLocationRoleType

short: Requested location
definition: The preferred location(s) where the request should actually be performed in coded or free text form: E.g. at home or nursing day care center, or as a reference to a specific Location. This element specifies the location for the overall request orchestration, but if may be overridden by the location element in specific actions.

Update the RequestOrchestration.action.location to be 0..* CodeableReference(Location)
Update the RequestOrchestration.action.location element definition to add:

If not specified, the action is expected to be performed at the location(s) specified in the root location element. If a location is specified in the action, it overrides the location(s) specified at the root.
- **Resolution Vote**: Lawrence McKnight/Howard Strasberg: 13-0-1
- **Vote Date**: 2026-09-23
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: Just like other request resources, there's a need for 'location' to indicate where the requested therapy needs to be delivered. This might be at home, an out-patient clinic, an in-patient facility, etc.
