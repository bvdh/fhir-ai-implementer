- **Resolution Description**: Changes to B&C text:

An alert condition becoming active is a trigger to start signaling.
The signal state is composed of two attributes: signal.activationState and signal.presence. A single alert signal as identified by signal.identifier may have multiple signal state segments over time. If the signal.identifier is the same across multiple signal instances, signal.period would be used to differentiate the signal instances.

Distinct identifiers indicate distinct logical signals.

A DeviceAlert is created when a device detects a specific, often safety-relevant, condition and records that condition as a distinct alert instance...

Also update the general example to demonstrate the newly introduced signal.identifier.

- **Description**: This ballot adds signal.identifier element.

The Background section explains that a logical signal can have multiple signal-state segments and that successive signal elements can use the same identifier to indicate that they are state changes of the same signal. It even describes initial signal creation as having a "unique signal.identifier."

However, DeviceAlert.signal.identifier has cardinality 0..*, and the specification does not clearly state when an identifier is expected or necessary.

This becomes important when a DeviceAlert contains several signal repetitions: without an identifier, a receiver may be unable to determine whether they represent:

different logical signals, or
successive states of the same logical signal.

Proposed change:

Add guidance such as:

"When multiple DeviceAlert.signal repetitions represent state segments of the same logical signal, the same signal.identifier SHOULD be present on those repetitions. Separate logical signals SHOULD use distinct identifiers."

Also consider updating the general example to demonstrate the newly introduced signal.identifier; the current example contains a signal but does not include the new identifier.
