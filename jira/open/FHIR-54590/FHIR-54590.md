- **Description**: Comment

The current R6 ballot text does not clearly describe how additional bindings are expected to be validated, particularly when:

the base binding is extensible,

the element is repeating, and

any=true is used to allow satisfaction of additional bindings across repeats.

It is also unclear when additional bindings are sufficient versus when slicing should be used to express distinct, enforceable binding requirements.
Why this matters

In practice, IG authors struggle to determine:

which additional bindings are directly testable in resource instances,

which represent application obligations or documentation only, and

when slicing is required to achieve predictable validation behavior.

This ambiguity leads to inconsistent IG designs and unpredictable validator outcomes.
Requested change

Please add explicit guidance describing:

which binding purposes are intended to be directly enforceable vs informational,

how binding strength on additional bindings interacts with base binding strength, and

when additional bindings should be used versus slicing for enforceable alternative or contextual bindings.
