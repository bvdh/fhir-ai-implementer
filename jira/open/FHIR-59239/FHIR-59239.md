# FHIR-59239: ImplementationGuide.packageId needs to be more clear on lowercase

- **Description**: I recognize that we likely can't change ImplementationGuide.packageId to be a datatype that does not allow uppercase, but we should have more clear guidance to the reader that it really should be lowercase. The definition on ImplementationGuide.packageId explains that it is used for the NPM name. But we should not expect our readers totally understand the NPM name rules. Please add to the definition or add a comment that lowercase is needed by NPM.

It might be possible that our tooling is automatically lowercasing it, but that does not help someone who is writing a dependency on an IG that says that the PackageId is something in uppercase.

Sushi throws a warning: Sushi: warn FooBar contains uppercase characters, which is discouraged. SUSHI will use FooBar as the package name.

Which is nice, but is too late; and it mentions some "discouraged" message that I can't find. I find NO discouraging comments about mixed or uppercase.
