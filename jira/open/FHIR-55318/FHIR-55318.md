### 4. Michelle Miller - 2026-05-19

WGM May 19, 2026 - Tues Q2 (FHIR-I)

FHIR Infrastructure Minutes WGM 202605 - Rotterdam - FHIR Infrastructure - Confluence

Lloyd described a use case where a future version of FHIR introduces a code that wasn't in R6.

Lloyd shared that Resource.implicitRules can be used (it is a uri with a description of what needs to be done to process/understand FHIR resource). You have to understand the rules in order to process the resource. For example, added/used for other use cases, V2 sends updated birthday, but don't want to wipe out other elements (e.g. name) not sent.

Encourage implementers to build into systems the elements that are mandatory (don't want them to take "easy" way out)

Put in a code for escape valve, but not other/unknown – too generic – those that are lazy will use other/unknown. Rob M. is counter proposing "unmappable" (smaller bucket, has specific meaning, forward change, but doesn't solve Lloyd's issue)

Jose believes adding "other" is the lesser of the evils (as compared to promoting and raising awareness to Resource.implicitRules)

Discussion (Pros/Cons) of implicitRules

implicitRule would be some codes will have a different code that is not in the value set for this version, only done in circumstances when cross-version code is present

AGAINST Resource.implicitRules

Concern is that Resource.implicitRules will be misused (non-conformant resources, loosen constraints)
The element pre-exists (and normative as well)

FOR Resource.implicitRules

Assuming we add a new code to R6 (fixes R6 for future codes added in the future). It can't fix the problem in prior releases since codes don't exist. The key is that other/unknown doesn't work in prior versions of FHIR
Could add "warning" and constrain URI to a hl7.org

Ruled Out (modifier extension)

Can't have modifier extension on codes (simple data type)

Proposal

Add new section in cross-version IG that talks about issue created by mandatory elements with required bindings.

Define the rule that says that if you use this implicitRule (URI is this section), you can always add _XV code provided that there is a a flag that allows it

Dragon warning in core spec that says while this is a get out of jail free card to do all kinds of things, realize that this break interoperability with anyone not in that closed community. This shouldn't be seen as a blessing of non-compatible exchanges as being truly FHIR-conformant.

New guidance will be issued to work groups (to revisit escape valve JIRAs) and instead defer to the cross version IG handling of this.
