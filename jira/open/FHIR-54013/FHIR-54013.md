# FHIR-54013: Make criticality an extension. Add rationale.

- **Description**: The distinction between allergy criticality and reaction severity is clear within the FHIR specification. However, many systems record a property called "severity", but they do so at the intolerance level, and few capture "criticality". This has led to confusion in attempts to map data from these systems into FHIR.

First, since the "criticality" property is not often implemented, it seems like an obvious candidate for exclusion by the 80/20 rule.

For systems that do use it, it seems valuable, but only in rare cases. Most providers expect that anaphylaxis carries a high level of risk, and that nausea in reaction to morphine is typically not dangerous. If these examples were marked "critical" and "not critical", all we have done is increase the documentation burden. Only in the case of divergence from the norm - e.g., that the nausea is judged to be critical - does this assertion have value, and even there, it would seem to require some supporting evidence to help the consuming provider process the assertion.

In addition to removing criticality from the core spec to an extension, the extension should require a rationale. A codable concept would support text in the near term and computable values if and when they are identified. The rationale value set, when built, should include a value for "Value chosen based on common experience with this substance and this symptom; i.e., no special information", in case any system actually requires its use.
