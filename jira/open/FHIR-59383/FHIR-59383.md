# FHIR-59383: Clarify representation of CDA document instance, set and version identifiers in DocumentReference

- **Description**: FHIR does not provide sufficiently clear and interoperable guidance for representing the identifiers of a versioned CDA document in DocumentReference.

A CDA document may contain:

ClinicalDocument.id: the identifier of this specific document instance/version;
ClinicalDocument.setId: the version-independent identifier shared by all versions in the document set;
ClinicalDocument.versionNumber: the version number within that set.

In FHIR R4, DocumentReference.masterIdentifier is described as the source-assigned identifier specific to this version of the document, with an explicit reference to the CDA Document Id. DocumentReference.identifier is described as containing other identifiers, including version-independent identifiers.

In R5, masterIdentifier was removed, and version was added. However, the R5 definition of DocumentReference.identifier says that it includes “version-independent identifiers”, while its requirements say that the identifiers are “specific to this instance of the document”. The comments also identify the CDA Document Id as an example. This leaves the intended representation of a CDA setId unclear.

The current R6 build describes DocumentReference.identifier primarily in terms of identifiers specific to the document instance. It therefore remains unclear where a version-independent CDA setId should be represented.

There is also no clearly identified standard Identifier.type code for distinguishing a document instance identifier from a document set or series identifier. Using Identifier.system for that purpose is not reliable: ClinicalDocument.id and ClinicalDocument.setId may use the same II.root, and Identifier.system represents the identifier namespace rather than its semantic role.

This ambiguity leads implementations to:

omit either ClinicalDocument.id or ClinicalDocument.setId;
define incompatible local Identifier.type codes;
use Identifier.system as a role discriminator;
assume that ClinicalDocument.id can be reconstructed from setId and versionNumber, although CDA does not generally require such a derivation.

Please provide a normative or clearly documented mapping for CDA document identifiers in R5 and R6.

The suggested mapping is:

ClinicalDocument.id → DocumentReference.identifier, representing the document instance identifier;
ClinicalDocument.setId → DocumentReference.identifier, representing the version-independent document set/series identifier;
ClinicalDocument.versionNumber → DocumentReference.version.

ClinicalDocument.id should not be considered redundant merely because setId and versionNumber are present, unless the source specification explicitly guarantees that the instance identifier can be derived from those values.

Please also provide an interoperable way to distinguish the two identifier roles. This could be accomplished by:

defining standard codes for Identifier.type, such as “document instance identifier” and “document set/series identifier”; or
documenting an existing terminology or another standard representation that implementations should use.

Identifier.system should continue to represent the identifier namespace, for example urn:oid:{II.root}{}, and should not be used to distinguish the identifier’s role.

Please add an example in which ClinicalDocument.id and ClinicalDocument.setId use the same II.root but have different extensions.

Cross-version guidance

Please document the intended transition from R4 to R5:

R4 masterIdentifier (CDA ClinicalDocument.id) → R5/R6 identifier with the document-instance role;
R4 identifier carrying CDA ClinicalDocument.setId → R5/R6 identifier with the document-set role;
CDA ClinicalDocument.versionNumber → R5/R6 version.

If an R4 implementation needs to pre-adopt DocumentReference.version, please identify or define the appropriate standard extension rather than requiring each implementation guide to create a local extension.

Acceptance criteria

The definitions and requirements for DocumentReference.identifier no longer conflict regarding version-specific and version-independent identifiers.
The specification provides an explicit mapping for CDA ClinicalDocument.id, setId and versionNumber.
Implementations have a standard interoperable mechanism for distinguishing document instance and document set identifiers.
An example covers id and setId values issued under the same identifier namespace.
Cross-version guidance is provided for migration from R4 masterIdentifier to R5/R6.
