- **Resolution Description**: Will update the #document canonicalization variant (Canonicalization Variants) from:

The Document Bundle.id and Bundle.metadata on the root Bundle are omitted prior to signing. This allows for a document to be copied from server to server

to

The Resource.id and Resource.meta on the root resource are omitted prior to signing. This allows for a document or artifact copied between servers to maintain its signature. Note the format name document is historical, even though this variant can be applied to any resource.

## Comments

### 1. Bryn Rhodes - 2026-08-26

Discussed on CRMI call and would like this pulled from the block vote.

1. It's not clear that generalizing document will work, because as written, it doesn't apply to content recursively.
2. Reviewed static, and that may apply, except that isn't it not stable across servers anyway because it includes ids as well as references to those server-specific ids?

So either, static should be modified to exclude all logical ids and references in the content or, we should define an "artifact" that is "static + no ids or references"

Unless we're missing something, static can't do what it is currently proposed to do, and so it should just be fixed and then we'll use that.
