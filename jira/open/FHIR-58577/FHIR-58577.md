- **Description**: I see in some Resources like Evidence, Evidence.name has a constraint warning that says "Name should be usable as an identifier for the module by machine processing applications such as code generation" and expression "name.exists() implies name.matches('^[A-Z]([A-Za-z0-9_]){1,254}$')"

But Group doesn't have that for Group.name and it's likely because the definition "A label assigned to the group for human identification and communication." and the Requirements: "Used to identify the group in human communication." But that's usually what the title element is for. And Group interfaces with the CanonicalResource where "title" is the human friendly name, and the "name" element is the computer friendly one.

Group.name also being human friendly seems like it could be a deliberate decision, so maybe there should be a Comment explaining why. But if Group.name was meant to be computer friendly, then the description and requirement needs to be updated, and there be an invariant for it to ensure the conformance.
