- **Resolution Description**: Will change "Specifies the format of the optional OperationOutcome Resource response to the kick-off request" to

"Specifies the format of the optional OperationOutcome Resource response to the kick-off request as well as the format of the eventual asynchronous response."

Under the last paragraph on status request (before the subheadings) will say "The status request SHOULD NOT send an Accept header. If it does provide one, it SHALL provide the same Accept header as was in the kick-off request."
- **Resolution Vote**: Bas van den Heuvel/Gino Canessa: 8-0-0
- **Vote Date**: 2024-10-07
- **Change Category**: Clarification
- **Change Impact**: Compatible, substantive
- **Description**: Does the Accept header in the initial request also suggest the format the result Bundle? Can the client override this by including an Accept-header in the status request?

My preferred solution would be to use the format indicated in http-message and, if absent, the one in the original request.
In the case any of the http-responses has FHIR data, it SHALL also include a Content-Type header stating the format of the data returned.
