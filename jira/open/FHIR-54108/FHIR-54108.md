- **Resolution Description**: Change the $expand property parameter definition from:

A request to return a particular property in the expansion. The returned property may include subproperties. May be either a code from the code system definition (convenient) or a the formal URI that refers to the property. Note that property names can clash, so using a URI is recommended. The special value '*' means all properties and their sub-properties known to the server

TO:
> If this parameter is valued, and applies to concepts in the code system, a concept property or sub-property SHALL be returned in the expansion. If this parameter value identifies a valid property, the returned property SHALL include the property and all sub-properties. If this parameter value identifies a valid sub-property, the returned sub-property SHALL include the sub-property and the parent property.

This parameter value may be either a code identifying a property or sub-property from the code system, or the URI that refers to the property or sub-property. A URI MAY be used to avoid property name clashes if required.

The special value “*” is shorthand for the server to return all properties and subproperties.

If this parameter is not valued, the server can return properties and sub-properties at the server's discretion.

Change the property input parameter on $lookup

From:

A property that the client wishes to be returned in the output. If no properties are specified, the server chooses what to return. The following properties are defined for all code systems: name, version (code system info) and code information: display, designation, and lang.X where X is a designation language code. These properties are returned explicitly in named out parameters with matching names, or in designations. In addition, any property codes defined by this specification or by the CodeSystem (CodeSystem.property.code) are allowed, and these are returned in the out parameter property

To:

If this parameter is valued, and applies to concepts in the code system, a concept property or sub-property SHALL be returned. If this parameter value identifies a valid property, the returned property SHALL include the property and all sub-properties. If this parameter value identifies a valid sub-property, the returned sub-property SHALL include the sub-property and the parent property.

This parameter value may be either a code identifying a property or sub-property from the code system, or the URI that refers to the property or sub-property. A URI MAY be used to avoid property name clashes if required.

The special value “*” is shorthand for the server to return all properties and subproperties.

If this parameter is not valued, the server can return properties and sub-properties at the server's discretion.
- **Description**: See attached spreadsheet documenting current and proposed parameter descriptions, as well as questions.

As part of this change proposal, suggestions are also made to use consistent references to concept code, concept, and code.

TI co-chairs suggest that a task force be formed to address the issues detailed in the spreadsheet, and address any other operations (e.g., $lookup) that might include similar parameters and issues.

### 3. Carmela A. Couderc - 2026-08-03

20260803

Current property parameter definition:

A request to return a particular property in the expansion. The returned property may include subproperties. May be either a code from the code system definition (convenient) or a the formal URI that refers to the property. Note that property names can clash, so using a URI is recommended. The special value '*' means all properties and their sub-properties known to the server

Update the property parameter documentation in $expand to:
> A request to return a particular property in the expansion. The returned property MAY include sub-properties. The parameter value could be either a code identifying a property from the code system definition (convenient) or the formal URI that refers to the property. Because property names can clash, a URI SHOULD be used. The special value '*' means all properties and their sub-properties known to the server SHOULD be returned with the expansion.

Discussion: ML described what Ontoserver does - most properties are returned. Sub-properties aren't defined and its not clear what property a sub-property is a "sub" of. What to return if property = parent? SNOMED has sub-properties, but in the code system, there isn't a parent property - but under the hood there is a parent. Sub-properties aren't well defined/described - not in the original 80/20. Ontoserver does support defining sub-properties using extensions for a specific use case. CodeSystem doesn't define sub-property.

Decision: we will discuss this parameter at the September 2026 WGM. CC to add to the agenda.
