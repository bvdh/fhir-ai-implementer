# FHIR-58712: The binding to MIME-type might be misleading

- **Related Page(s)**: DatatypesElementDefinition
- **Description**: In the resolution of a ticket against the FHIRsmith server (MimeType (`urn:ietf:bcp:13`) `$validate-code` does not enforce membership for a Required binding · Issue #278 · HealthIntersections/FHIRsmith) it is stated that this ValueSet should check for:

the definition is clear: any valid mime type and that is not any registered mime type. If you want to restrict to registered mime types, make a value set for that

The description of the ValueSet states::

Include all codes defined in urn:ietf:bcp:13 version Not Stated (use latest from terminology server)

This suggests that this is a list not a pattern. Using a ValueSet also suggests that there is a list against the MIME-type is checked.

In fact BCP13 only defines the MIME-type pattern not the list.

I think this is approach is misleading. If we are checking for a pattern, we should not use a ValueSet. A constrained might be better but will cause issues when the definition changes.
Also expansion and other typical terminology operations do not work on such a Valueset which is not a ValueSet.

I suggest that we update the description of all fields that refer to MIME type that the MIME type needs to be fomatted in accordance to the BCD13 pattern: type/subtype

In addition we should create an extensible binding that lists all codes registered with IANA: https://www.iana.org/assignments/media-types. The ValueSet should be regularly updated to reflect the current list so the binding should not pin the version.
