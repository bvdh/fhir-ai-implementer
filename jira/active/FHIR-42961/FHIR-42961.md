- **Resolution Description**: Per FHIR-51099, this element is deprecated.

Ensure that Bundle.signature is flagged as deprecated and has text updated to reflect that.
- **Resolution Vote**: Bas van den Heuvel / Corey Spears : 8-0-2
- **Vote Date**: 2026-07-06
- **Change Category**: Correction
- **Change Impact**: Non-substantive
- **Description**: The bundle currently has signature cardinality of 0...1, this is limiting in that only one party may sign a document for one purpose. Multiple parties may want to sign the same bundle for different purposes (e.g. Proof of Origin, Proof of Receipt etc.). I would suggest changing the cardinality to 0...*.

### 2. Bas van den Heuvel - 2026-10-20

The Bundle.signature element was deprecated (FHIR-51099) and subsequently removed (FHIR-53722), so the cardinality change is not needed. The Bundle notes (bundle-notes.xml, "Signatures" section) still claimed Bundle has a signature element. They now say the element was deprecated and removed, and link to the Provenance-based signing guidance in signatures.html#Bundles. The worked example in signatures.html is not part of this resolution.

Commit: https://github.com/bvdh/fhir/commit/32df21502cce255b51d037af4dcc5c6ce4863918

### 4. Grahame Grieve - 2026-07-01

Reverted previous resolution: Persuasive with Modification made 2025-12-15 00:00:00.0 with vote Gino Canessa / Yunwei Wang: 8-0-1//(Impact: Compatible, substantive; Category: Enhancement; Version: null)//We will define a new extension called "AdditionalSignature" of type 0..* signature, context Bundle

Short: More signatures

Definition: Additional signatures that apply to the Bundle content (i.e. where a single Bundle.signature is not sufficient)

Comment: There is no distinction in meaning between the signature repetition that appears in Bundle.signature vs. those that are sent in this extension. Systems and profiles SHALL NOT ascribe different meaning to signatures sent in Bundle.signature vs. here.

Requirements: This is handled as a separate element rather than increasing the cardinality for Bundle.signature for backward compatibility reasons. If this element becomes widely used, we'll evaluate migrating the extension to Bundle.
