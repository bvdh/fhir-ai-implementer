## Comments

### 1. Jose Costa-Teixeira - 2026-10-06

Applied in PR 4339. The status binding was settled by FHIR-59543 (PublicationStatus), applied in the same PR.

### 2. Lloyd McKenzie - 2026-10-04

I think "not to be used" is a formulary thing, not an aspect of the Medication instance. And I'd ask why entered-in-error isn't used for any of the other canonical resources. I don't think Medication is 'special' there.

### 3. Jose Costa-Teixeira - 2026-10-04

We should keep just one "active" - perhaps the one from canonical CS ?

Because this is optionally canonical, not always:

For retired and inactive: a record of a product may be currently inactive (i.e. this product is not to be used this year because of reasons). I read "retired" as more final.
For entered-in-error, similar: an instance may be entered in error.

For both of these, if this is not OK, I think we should rather remove it than to let it block the change

### 4. Lloyd McKenzie - 2026-10-04

You won't be able to have a valueset bound to a 'code' element that contains 'active' from two different code systems. Also, having both 'retired' and 'inactive' will be confusing. If none of the other definitional resources need entered-in-error, why would Medication be any different?
