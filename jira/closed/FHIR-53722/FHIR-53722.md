- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: FHIR Infrastructure
- **Outstanding Negatives**: Normative
- **Related Artifact(s)**: MetadataResourceActivityDefinitionBundleCodeSystemConceptMapEventDefinitionLibraryMeasureNamingSystem
- **Resolution Description**: FHIR-I specific resolutions:

Bundle.signature - remove the element - was TU since R4, should not remain
StructureDefinition.keyword - is flagged as deprecated, will see why it is not rendering. This element cannot be removed due to already being normative and will remain in the spec, flagged as deprecated.
MetadataResource.topic - is flagged as deprecated, will see why it is not rendering. Will remove the element from the abstract resource. Will keep the search parameter but update it to search on useContext with code 'topic'. Note that all of the derived resources will need to have the element removed (or definition updated to no longer be derived if they talk to us and explain why) at the same time.
OperationOutcome.issue.location - remove the element: deprecated since R4

Guidance to other WGs:

If the element has the deprecated flag since R4, remove the element.
If the element has a deprecated comment and a trial use flag, the resource was trial-use in R4, or the element has been added in R5 or later, remove the element.
If the element has a deprecated comment and no flag, add the deprecated flag.

Have created sub-tickets for other work groups.
- **Resolution Vote**: Grahame Grieve/Gino Canessa: 13-0-0
- **Vote Date**: 2026-02-02
- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Description**: A number of elements remain in R6 ballot 4 that are (intended to be) marked as deprecated.

It seems odd to still have deprecated elements in a new major version intended for normativity. Doing so requires FHIR models & consumers to consider an element that is explicitly indicated as something that should not be used.

As far as I can tell, except for Observation.bodySite, the following elements (or resources) were either Trial Use or Deprecated in R5, which seems to meet the criteria for withdrawing them in R6. (per definition of Trial Use or per http://hl7.org/fhir/versions.html#deprecation )

If the element is truly obsolete, it should be removed. Or if it is expected to be maintained for backwards compatibility, it should not be considered deprecated.

Note: the deprecation flag doesn't seem to be rendered into the R6-ballot4 StructureDefinitions, but field descriptions still indicate these as being deprecated, and the deprecation still exists in the raw github files.

This makes it harder to find all deprecated fields, but here is a hopefully complete list:

Bundle.signature

ActivityDefinition.topic

CodeSystem.topic

ConceptMap.topic

EventDefinition.topic

Library.topic

Measure.topic

Measure.guidance

Measure.subject[x]

MetadataResource.topic

NamingSystem.topic

Observation.bodySite

OperationOutcome.issue.location

PlanDefinition.topic

ServiceRequest.specimen

StructureDefinition.keyword

ValueSet.topic
