- **Resolution Description**: Propose defining a new extension in the Extensions IG:
http://hl7.org/fhir/StructureDefinition/package-source

Extension is a complex extension containing:

packageId: id 1..1 - NPM-style package id/name.
version: string 0..1 - Package version - not required but strongly encouraged. Note that this SHALL be a SemVer-compatible version identifier.
uri: uri 0..1 - Canonical root URL for package. Comment: use of this may be required in certain contexts, e.g., if packages are not hosted in NPM-style package servers, CRMI-style library definitions, etc.

Context:

Any resource.
- **Resolution Vote**: Bryn Rhodes / Grahame Grieve : 15-0-0
- **Vote Date**: 2024-02-26
- **Change Category**: Enhancement
- **Change Impact**: Non-substantive
- **Description**: In addition to canonical URLs (e.g., ImplementationGuide, OperationDefinition, etc.), CapabilityStatement instances should provide package and (optionally) registry information.

For example, if a server supports http://hl7.org/fhir/us/core/StructureDefinition/us-core-patient, it would be nice to know that the clients should load hl7.fhir.us.core|5.0.1, and that it is available on http://packages.fhir.org.

This information could either be general to a CapabilityStatement (e.g., a root element that lists package name, version, and (optional) registry URL), or as extensions on canonical URLs.
