# FHIR-48737: Missing description of how primitive fhir types that only contain an extension should behave with functions like toString

- **Summary**: Missing description of how primitive fhir types that only contain an extension should behave with functions like toString

- **Related Page(s)**: FHIRPath (fluentpath)
- **Related Section(s)**: Using FHIR types in extensions, or possibly a new section
- **Resolution Description**: Will update the documentation of toString to indicate that if it is evaluated on a simple type with no value, the result is {}.
- **Resolution Vote**: Grahame Grieve/Bryn Rhodes: 11-0-0
- **Vote Date**: 2024-11-18
- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Applied for Version**: R6
- **Description**: There's a bug in the JAVA implementation of the toString() function that returns the text "null" if a primitive has no value and just an extension (which will be common with data absent reason - DAR).

There's no indication if this should return {} or an empty string "".

I think it should be {}.
