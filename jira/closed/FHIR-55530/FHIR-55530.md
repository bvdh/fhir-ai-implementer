Issues:

1) This duplicates ways to record things without guidance on when to use which approach, leading to inconsistent implementation.

2) Provenance provides critical context of when, who, and why that `relatesTo` lacks because it conflates the "entity" with the "activity".

3) signs is problematic. A single signature could be recorded in three different places with no guidance on which is authoritative:

Composition.relatesTo.type = "sign"
Composition.attester
Provenance.signature

4) Do the relatesTo codes for document lifecycle overlap with `Composition.status`? (For example: the code "amends" for the status "amended")

Recommendations:

1) Consider Removing Overlapping Codes:`derived-from`, `transforms`, `amends`, `corrects`, `replaces`, `retracts`, and `signs` from the Artifact Relationship Type value set when used in clinical resources like Composition.

2) If keeping the codes, provide guidance on how `relatesTo` relationships correlate with `Composition.status` transitions.

3) Provide guidance discussing the boundaries between these two approaches.

for example:
Use `relatesTo` for static bibliographic and structural relationships. Use Provenance when the relationship represents an activity that occurred at a specific time by a specific agent.

### 2. Gay Dolin - 2026-06-24

Please create a level 4 section under 2.8.2 Boundaries and Relationships and add the text as written

2.8.2.1 Relationship of Composition Elements to Provenance:

Some Composition elements overlap with information that may also be represented using Provenance. Composition elements describe information intrinsic to the Composition and SHOULD be used in preference to Provenance. Provenance SHOULD be used when additional information about the activity that created, revised, transformed, removed, or signed the Composition is required. When both are present, the information SHOULD be consistent.

Examples include:

Amendment or correction: Composition.status describes the clinical standing of the current Composition, while Composition.relatesTo identifies the previous artifact—for example, status = corrected with relatesTo.type = corrects. Provenance may additionally identify the revision activity, prior entity, responsible agents, time, and reason.
Derivation or transformation: relatesTo.type = derived-from or transforms states the relationship between the artifacts. Provenance may describe the activity and the source entities used to produce the Composition.
Retraction: relatesTo.type = retracts states that the Composition retracts another artifact. This is distinct from Provenance.entity.role = removal, which describes how an entity was used in an activity involving its removal.
Attestation and signature: Composition.attester identifies responsibility for the accuracy of the Composition, while Provenance.signature records a signature on the target. relatesTo.type = signs is used only when the Composition itself is a signature artifact for the target, not merely to indicate that the Composition was signed.
