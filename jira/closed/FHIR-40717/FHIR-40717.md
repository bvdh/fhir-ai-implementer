## Comments

### 1. Carmela A. Couderc - 2024-01-29

valueset-unclosed discussion:

The intent is to communicate that a terminology server cannot compute all of the potential concepts in an expansion. It is not intended to communicate too-costly.

### 2. Carmela A. Couderc - 2024-01-29

Discussed on the 2024-01-29 Q4 WGM

https://hl7.org/fhir/extensions/StructureDefinition-valueset-toocostly.html

The context is valueSet.expansion, and is a response to the operation $expand

We looked at this other extension: https://build.fhir.org/ig/HL7/fhir-extensions/StructureDefinition-valueset-unclosed.html which is a statement that the expansion is not complete because they can't be computed (post-coordination), not necessarily a response to an operation.

https://chat.fhir.org/#narrow/stream/179202-terminology/topic/Parameters.20to.20.24validate-code/near/308311130

We noted that in the STU3 value set expansion profile, there is a https://hl7.org/fhir/STU3/expansionprofile-definitions.html#ExpansionProfile.limitedExpansion

There is also an operation outcome code = too-costly.

This extension is only used in STU3 and the information it provides should be communicated as a warning, or as an operation outcome code = too-costly for a terminology server based on a more recent FHIR version.
