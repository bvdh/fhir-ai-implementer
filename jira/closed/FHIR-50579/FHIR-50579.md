- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: FHIR Infrastructure
- **Related URL**: https://hl7.org/fhir/6.0.0-ballot3/obligations.html
- **Related Page(s)**: Obligations
- **Related Section(s)**: 5.2.1
- **Resolution Description**: Will change

"The base FHIR specification is intended to be independent of any particular implementation context, so no elements are flagged as mustSupport=true as part of the base specification, and no obligations are defined for any elements (except for an example profile)."

to

"The base FHIR specification is intended to be independent of any particular implementation context, so no elements are flagged as mustSupport=true or assigned obligations as part of the resource definitions in base specification (though obligations and/or mustSupport are used in some profiles defined in the base specification)."
- **Resolution Vote**: Corey Spears/Yunwei Wang: 5-0-0
- **Vote Date**: 2025-06-02
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Applied for Version**: R6
- **Description**: The "Implementation Obligations" page states that

"

The base FHIR specification is intended to be independent of any particular implementation context, so no elements are flagged as mustSupport=true as part of the base specification, and no obligations are defined for any elements (except for an example profile).

"

This seems misleading given the existence of the Vital Signs profile, which has direct implementation requirements and uses mustSupport.
