- **Description**: The fourth bullet in the third list describes "

"Identifying a node in a DICOM Structured Report SOP Instance from which an Observation is derived"

It is not allowed to reference into a content item from outside the DICOM SR (see David Clunie's book on DICOM SR:
"The reference mechanism does not permit references to nodes within other documents. That is, one can only have “by reference” relationships with content items within the same document. One can refer to entire documents by using the COMPOSITE value type, but there is no provision to reference individual items within that document. Conceptually, this would be possible by a combination of the SOP Instance UID of the target document and a referenced content item. However, it is forbidden as a matter of policy, on the grounds that the “internal arrangement” of a referenced document might change, outside the control of the creator of a referencing document)"

The decision to support referencing into a content item should be revisited. Another option

### 2. Jonathan Whitby - 2026-09-15

The resource originally used Observation UID to reference nodes within the content tree but feedback from DICOM WG-06 – including David Clunie specifically – was that this is not widely used and we should use the content item reference mechanism instead.

I agree this conflicts with what David has previously said and we should seek clarification from David / WG-06 that his views on this have changed and it is not in fact DICOM policy (anymore).
