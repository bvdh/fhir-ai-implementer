### 5. AnjaSchwab - 2026-03-17

We strongly disagree that relying solely on the implicit ordering via ElementDefinition.orderMeaning is sufficient in this context.
Given that the sequence of dosage instructions is treatment-critical and can directly impact clinical interpretation and safety, the order must be represented explicitly rather than inferred.
We therefore strongly agree with the suggestion to introduce an explicit sequence number element to ensure unambiguous representation of dosage order across different implementations.

### 6. Jose Costa-Teixeira - 2026-01-28

As per the comment, we have a technical mechanism to assert that order is important.
This should be added and some narrative to enforce it (as per WG discussion 28/Jan/2026).

However, we invite the requester(s) to come up with additional arguments for this before advancing.

Note that an explicit sequence number allows sequences like 1, 2, 4, 3 - which is accepted if we assume that the applications will always sort this by sequence.

### 7. Jose Costa-Teixeira - 2026-01-28

https://build.fhir.org/conformance-rules.html#cardinality says:
For elements that have cardinality > 1, the order in which they appear may have meaning. Unless the element definition (either in this specification or the extension) defines a meaning to the order explicitly (using ElementDefinition.orderMeaning), the meaning of the order is not defined, and implementations are allowed to reorder the elements.

This would technically allow us to declare that order in steps is important.
