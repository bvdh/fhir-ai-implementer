# FHIR-49666: CapabilityStatement.rest.resource.type required binding is too narrow

## Metadata

- **Summary**: CapabilityStatement.rest.resource.type required binding is too narrow
- **Created**: 2025-01-27
- **Updated**: 2025-11-01
- **Resolved**: 2025-06-23
- **Status**: Applied
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Grahame Grieve
- **Resolution**: Persuasive with Modification
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: FHIR Infrastructure
- **Related Artifact(s)**: CapabilityStatement (Conformance)
- **Resolution Description**: Will change the data type from code to URI and will relax the binding as defined
- **Resolution Vote**: Gino Canessa/Nikolai Ryzhikov: 12-0-0
- **Vote Date**: 2025-06-23
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Applied for Version**: R6
- **Description**: The binding for CapabilityStatement.rest.resource.type is required, and bound to a value set that only includes concrete resources. This is problem because CapabilityStatements are used across versions, and also there's reason to use it with logical models (= custom resources).

It should work the same way as ElementDefinition.type.code (https://hl7.org/fhir/elementdefinition-definitions.html#ElementDefinition.type.code) so extensibility is possible.

- **Jira**: https://jira.hl7.org/browse/FHIR-49666

## Comments

### 1. Lloyd McKenzie - 2025-06-09

We're happy to make the binding change, however there's also a need/desire to change the data type from code -> uri, and that is currently against our rules for normative changes.

See https://jira.hl7.org/browse/FHIR-51051
