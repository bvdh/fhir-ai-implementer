# FHIR-55509: Meaning of "computer friendly" is unclear

- **Raised in Version**: R5

- **Related Artifact(s)**: Composition
- **Resolution Description**: Background

Composition.name was added in R5 based on https://jira.hl7.org/browse/FHIR-34159:

Summary - Based on the Evidence Reports Use Case and "common pattern in FHIR to have both (human-readable = title; computer-readable = name)" which is more of FHIR conformance and definitional resource pattern, but "very little downside" to having it here as an optional element.

Although Composition is not a conformance or definitional resource, this element, including its definitions, was copied from the CanonicalResource inheritance pattern.

Current Details:

Composition.name

Element Id
Composition.name

Definition
A natural language name identifying the title. This name should be usable as an identifier for the module by machine processing applications such as code generation.

Short Display
Name for this Composition (computer friendly)

Cardinality
0..1

Type
string

Requirements
Support human navigation and code generation.

Summary
true

Comments
The name is not expected to be globally unique. The name should be a simple alphanumeric type name to ensure that it is machine-processing friendly.

Update the element details and add the same invariant from the CanonicalResource inheritance pattern.

Change:

Short: "Computer-friendly name"
Description: "A machine-friendly identifier suitable for code generation. For example, "ClinicalDocument" or "Composition_v2".See the Constraint description."
Comments: "The name is not expected to be globally unique. This field is used primarily by computers while the title field includes information for human-display. Composition.type is used to provide a CodeableConcept for the document type when available while Composition.name is an uncoded string. Composition.identifier is used to identify the specific instance of a document."
Constraints:

Key: cmp-4
Level: Warning
Description: "Name should start with an uppercase letter (A–Z), be 2 to 255 characters long, and contain only letters, digits, and underscores. Whitespace, hyphens, and other punctuation are not permitted."
FHIRPath: name.exists() implies name.matches('^[A-Z]([A-Za-z0-9_]){1,254}$')

(Create a FHIR-I followup tracker, FHIR-57484, to update their lousy definition and constraint description.)

- **Description**: Why do we need the "computer friendly" Composition.name element when we have Composition.type and Composition.identifier? What use cases cannot be met without Composition.name?

I'd suggest that the description be updated to clarify the intended use for this element.
