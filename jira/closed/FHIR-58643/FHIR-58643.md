# FHIR-58643: MedicationRequest.isRecordOfRequest needs to be dropped

- **Resolution Description**: We will remove the element and provide the following guidance in the scope and usage, after
"The MedicationRequest resource is a "request" resource from a FHIR workflow perspective - see Workflow Request"
add - it serves as an authorization, which doesn't make it necessarily actionable, unless it has the 'actionable' tag set, or used in combination with a Task resource or in specific workflows - more information on the workflow pages.
- **Resolution Vote**: José Costa Teixeira / Frank McKinney : 7-0-0
- **Vote Date**: 2026-10-19
- **Change Category**: Enhancement
- **Change Impact**: Non-compatible
- **Request in-person**: Lloyd McKenzie
- **Description**: If a Request has an intent of 'order', then it's automatically a 'record of the order' and never serves, by itself, as a request for fulfillment. As per the workflow pages, if a copy of a MedicationRequest is intended to be actionable, it has to have the 'actionable' tag. Multiple copies of the Request could exist, one with the 'actionable' tag and the others without it and would have identical content - and more importantly, could be validated against the same digital signature.

If there's confusion amongst implementers with respect to this, the solution is to add a link to the workflow page to provide that guidance.
