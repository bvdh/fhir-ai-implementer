Marks that the expansion is incomplete, and values other than those listed may be valid. This may be used when technical limitations prevent a full expansion, or when post-coordinated codes are allowed, and no complete expansion can be produced.

- **Description**: The extension http://hl7.org/fhir/StructureDefinition/valueset-unclosed needs some additional documentation - when is it safe to return this, (always?) as opposed to an error, what client obligations come with it's use?

My opinion: unless a client indicates that it's asking for a partial expansion, then it $expand should return an error, but if a client asks for a partial expansion, it gets this with the expansion that's returned.

### 6. Grahame Grieve - 2024-01-31

Agree that we need to define how to request an unclosed expansion. I have a parameter _incomplete=true that I pass from the client to indicate that I'm prepared to handle an incomplete/partial expansion.

It is extremely valuable to have this facility. Any code system that has a grammar - SCT - where the value set doesn't exclude post-coordinated codes, which is the vast majority of value sets, then they can't be expanded. Or the expansion is lying when it doesn't list post-coordinated codes. Either way, it's still very useful to get an expansion but necessary for the client to know that codes other than those in the expansion might be valid

In principle, it's useful to know that the expansion is incomplete even if you're not privy to the reason why, but it would be useful to inform the client as to why. But for me, the only reason I've found so far is post-coordination, so I just know that's the case

### 7. Peter Jordan - 2024-01-30

Do we have a clear definition of a 'partial expansion'. The only reference I can see in the core FHIR specification is to 'part' expansions in relation to paging large expansions. The extension refers to 'incomplete' expansions - is that synonymous with 'partial'. I'm obviously missing something here (a custom input parameter to $expand?), but I can't see how to request an incomplete/partial expansion (other than via the offset and count input parameters to $expand).
