# FHIR-48492: Un-deprecate jurisdiction element in various resources

## Metadata

- **Summary**: Un-deprecate jurisdiction element in various resources
- **Created**: 2024-10-03
- **Updated**: 2025-10-02
- **Resolved**: 2025-05-14
- **Status**: Applied
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Elliot Silver
- **Resolution**: Persuasive with Modification
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R6
- **Work Group**: FHIR Infrastructure
- **Related Artifact(s)**: CanonicalResourceCapabilityStatement (Conformance)CodeSystemConceptMapGraphDefinitionImplementationGuideMessageDefinitionNamingSystemOperationDefinitionSearchParameterStructureDefinitionStructureMapValueSet
- **Resolution Description**: 1. Undeprecate the jurisdiction element in all locations it appears and remove any deprecation notes.

2. Change the definition of the jurisdiction element in all locations it appears

from:

A legal or geographic region in which the value set is intended to be used.

to:

A legal or geographic region in which the authority that maintains the resource is operating. In general, the jurisdiction is also found in the useContext. The useContext may reference additional jurisdictions because the defining jurisdiction does not necessarily limit the jurisdictions of use.

3. Add comprehensive examples of jurisdiction and useContext

4. Replace all the jurisdiction value set bindings with http://terminology.hl7.org/ValueSet/jurisdiction as the other is currently deprecated.
- **Resolution Vote**: Grahame Grieve / Gino Canessa : 22-0-0
- **Vote Date**: 2025-05-14
- **Change Category**: Correction
- **Change Impact**: Compatible, substantive
- **Description**: The jurisdiction element in many resources was inappropriately deprecated in R5 and should be returned. The associated value set should also be un-deprecated.

The related artifacts listed are conformance artifacts, however, this probably should be applied to all locations where jurisdiction was removed or deprecated in favour of useContext.

- **Jira**: https://jira.hl7.org/browse/FHIR-48492

### 6. Grahame Grieve - 2024-10-03

See Specifying jurisdiction

There are multiple reasons why this is a good idea:

The way the jurisdiction element has ended up being used is that it identifies the defining jurisdiction. This is not necessarily the same as the list of jurisdictions where the content is appropriate for use (as deemed by some authority).
Note that this doesn't quite match the definition, so I propose "Jurisdiction that defined this {title}, and where it is expected to be used" with a comment of "Note that other jurisdictions might make use of this {title} and might be listed in useContext if that happens"
the package ecosystem is cross version, and deprecating jurisdiction is painful for that
the same applies to the IG publisher

Irrespective of whether the element is un-deprecated, the value set should be anyway
