- **Description**: In the vital signs profiles, including those for blood pressure and body temperature, it is no longer allowed to have an additional code next to the mandatory LOINC code. This applies to Observation.code.coding element where multiple codings are allowed as long as they have the fixed code and also to the Observation.component.code.coding elements for systolic and diastolic blood pressure.
The attached example generates 3 errors on validation against R6. One for the base code element and one for each component code element.

### 9. David Barwin - 2026-06-10

Tracked this down. It was changed between 6.0.0-ballot1 sliced and 6.0.0-ballot2.

This is the ticket and commit:
https://jira.hl7.org/browse/FHIR-46418
https://github.com/HL7/fhir/commit/71babbf5ac7b63bce2d61d23ecf4f9d8c1bae164

Based on the ticket it is not clear that this is an intended change.

In R5, this was modeled as code.coding with an open slice and a required LOINC slice. That means “one LOINC coding is required, and other codings may also be present.” R6’s patternCodeableConcept shape has lost that open-coding behavior.

### 10. David Barwin - 2026-06-10

I added Erik's example locally and had a green build. I've put up a draft PR to try the same on CI: https://github.com/HL7/fhir/pull/4139

I think Erik is right though, and while the kindling build isn't failing, the equivalent in publisher might blow up for this example.

The BP profile has open slicing on Observation.component, but not on Observation.code.coding or Observation.component.code.coding.

Observation.code.coding 1..* must always have a system fixed http://loinc.org and code fixed 85354-9.

So extra components are allowed. Extra codings inside the constrained code elements are not allowed by the current profile shape.

In R5, the BP profile explicitly allowed additional codings: https://hl7.org/fhir/bp.html#10.1.19.44.2. It also defines open slicing on Observation.code.coding and Observation.component.code.coding.

The R5 page shows Observation.code.coding as “Slice: Unordered, Open by value:code, value:system”, with a required coding:BPCode slice for LOINC 85354-9. Same pattern for systolic and diastolic component codings.

So this is a breaking change between R5 and R6. Is this intentional and/or acceptable? I do not know.
