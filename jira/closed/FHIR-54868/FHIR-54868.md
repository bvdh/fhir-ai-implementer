- **Description**: Why is the element min = 1? __

We updated the __ US Core Condition Encounter Diagnosis Profile (https://confluence.hl7.org/spaces/AP/pages/345085086/US+Core+Condition+Encounter+Diagnosis+Profile) to remove all the status, because they are not available or populated for this use-case. However, the R6 Condition resource made Condition. clinicalStatus mandatory.

The R6 Condition comments even states this as well:
"...For conditions that are not problem list items, the clinicalStatus may be unknown. For example, conditions derived from a claim are point in time, so those conditions may have a clinicalStatus of unknown"
looking at the the category binding :

problem-list-item
encounter-diagnosis
diagnostic-report-impression

only "problem-list-item" may have a clinicalStatus

Therefore in many use cases it will be empty or "unknown"

Recommendation:

Change back to min =0 and updating the guidance to state it SHOULD be populated when the category is a problem-list-item.

### 5. Michelle Miller - 2026-07-09

rhausam We previously had an invariant to require Clinical Status when category was Problem List Item, so the cardinality (of clinicalStatus) was effectively required for problem list entries. ### 6. Robert Hausam - 2026-07-09

I don't necessarily feel too strongly about whether we could relax the cardinality of Condition.clinicalStatus back to 0..1. But possibly we could consider that. The change to make it 1..1 wasn't actually part of the original request in FHIR#29409, but it ended up that way in the ticket resolution, apparently (mostly) because 'clinicalStatus' is a modifier element. But the stated reason for 'clinicalStatus' being a modifier element is "This element is labeled as a modifier because the status contains codes that mark the condition as no longer active.", which actually seems to be rather suspect as a justification for that. The reasons for the "status" elements in other clinical resources being labeled as a modifier seem to be because the status may be 'entered-in-error', in which case the meaning of the resource is entirely changed. That makes more sense. But that is not the case for Condition.clinical-status, as the value set does not include the 'entered-in-error' code (it's instead in 'verification-status').
