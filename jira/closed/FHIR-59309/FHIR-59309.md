- **Summary**: MedicationRequest doesn't allow for AI produced Medication prescription

- **Status**: Applied

- **Related Artifact(s)**: MedicationRequest
- **Resolution Description**: We will add Device to informationSource
requester and performer already support Device and DeviceDefinition respectively.
- **Resolution Vote**: Jose Costa Teixeira / Chris Cannon : 10-0-0
- **Vote Date**: 2026-09-22
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: MedicationRequest has 3 participation elements:

informationSource
recorder
performer

none of these allow for a Device, which would allow for an AI to be one of these. This should be fixed.

Note about AI participations: the question is not whether we would like an AI to do this, or think that it's good practice. The question is: is it impossible for an AI to do this? if it's not, then Device should be one of the possibilities. Note that the participant pattern includes Device (partly for this reason), so not allowing it is also a deviation from the workflow pattern anyway.

It is likely insufficient, but isn't incorrect to be there. You could ask for the medication to be administered with a nebulizer, without knowing which specific serial number of device. On the other hand, there may be cases where you do know the specific device instance.

### 3. Elliot Silver - 2026-09-21

Consider whether specific device instances (Device) or models/SKUs of device (indicated by a device type code, or a canonical reference to a DeviceDefinition), or a class of device (device type code) are needed.
