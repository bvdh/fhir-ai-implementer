- **Description**: An example of a search on Patient is given. The page proceeds with the following example assert:
Verify that the search operation returned the right resource type:{}

<action>

<assert>

<resource value="Patient"></resource>

</assert>

</action>
It seems to me that the right resource type returned for a search would be Bundle (containing 0..* Patient resources).

The two following examples (containing `path` and `compareToSourcePath` elements which are to be deprecated in R6) also ignore that the Patient resource should be returned inside of a Bundle.

### 2. Richard Ettema - 2026-08-10

Confirmed that the TestScript search example asserts are incorrect. The resource type needs to be changed from 'Patient' to 'Bundle'.

In order to provide more example asserts use of FHIRPath expression the examples will be updated to use the 'expression' elements rather than 'path'.

Proposed new content:
Verify that the search operation returned the correct Bundle resource type:

<action>
<assert>
<resource value="Bundle" />
</assert>
</action>

There are many ways to verify that the search operation returned the expected, matched Patient:

Explicitly compare the elements to known value:

<action>
<assert>
<expression>
<expression value="Bundle.entry[0].resource.birthDate"/>
</expression>
<sourceId value="R1"/>
<value value="1974-12-31" />
</assert>
</action>

The sourceId element is pointed to the responseId value of the search operation. If no sourceId is specified, then test engines will use the response of the last operation in the test script even if responseId was not specified in the operation.

The expression element holds a FHIRPath expression against the response body contents.

Compare the elements in response to elements in another fixture that is either dynamically set by responseId or defined statically by the fixture element at the top of the script:

<action>
<assert>
<compareToSourceId value="F1"/>
<compareToSourceExpression>
<expression value="Patient.birthDate"/>
</compareToSourceExpression>
<expression>
<expression value="Bundle.entry[0].resource.birthDate"/>
</expression>
</assert>
</action>
