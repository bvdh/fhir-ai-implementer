- **Resolution Description**: Will define a new 'standard' extension called expression-coding 0..* with type Coding and context of Expression. Will have an example binding to LOINC.

- **Applied for Version**: R6
- **Description**: Currently, Measure.group.population.criteria has the ability reference an expression, but not by way of a coding system, e.g., LOINC that provides the fundamental definition. We propose to add Expression.code CodeableConcept 0..1 enabling a re-use of expressions using a coding system for the base definition where multiple equivalent expressions (e.g., CQL vs. FHIR Path vs. SQL or whatever represent the same logical/conceptual expression.

### 8. Bryn Rhodes - 2023-10-05

So a proposed disposition is:

Add a code 0..1 CodeableConcept element to the Expression datatype:

Short: Meaning of the expression
Definition: A code that identifies the meaning of the expression. For example, "Number of Beds"
Comment: There are formula and procedures that are used to compute/evaluate/product an observable value or assessment for an entity. These observable values are also coded in LOINC or another terminology system with an associated definition. The idea is that some measures may have codes that reference a (perhaps uncomputable, but somehow humanly interpretable into code) definition for how to compute them in addition to being represented in a computable expression. What we want is a way to apply a code to those computations.

### 9. Bryn Rhodes - 2023-10-05

Summarizing the discussion from an email thread, the intent of this change is to support identifying the expression as equivalent to some code in a coding system, for example a LOINC code for "Number of Beds" could be used to provide meaning for the expression. There are formula and procedures that are used to compute/evaluate/product an observable value or assessment for an entity. These observable values are also coded in LOINC or another terminology system with an associated definition.
