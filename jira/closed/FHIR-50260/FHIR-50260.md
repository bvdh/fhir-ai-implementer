- **Resolution Description**: We will add a comment to both the lowerLimit and upperLimit to say "These values are scaled in the same manner as the data values. I.e. to find the true limit, multiply this value by the factor and add the origin."

We're choosing to go with this interpretation because the one example we have in the spec that has limits (in Observation) uses this approach.

We will also add the following to the description of the data type:

"If there is a need to capture dimensions that differ in scale, origin, limits, etc. this is typically done by having multiple SampledData instances - one in each Observation.component where the components represent different dimensional subsets."

- **Description**: It is unclear whether SampledData.lowerLimit and SampledData.upperLimit are to be interpreted as scaled values or as original non-scaled values. The text needs to clarify this.
The assumption I and others made is that these values are not scaled and that the interval [lowerLimit..upperLimit] represents all possible measured values for a sample.

Proposed text:

The lowerLimit, when present, represents the lowest possible measured value and is not scaled. Similarly the upperLimit, when present, represents the highest possible measured value and is not scaled. The range [lowerLimit..upperLimit] can be used by visualisation tools for scaling when representing sampledData graphically.

And although submitted on FHIR R4, this is still applicable in R6 as well.

And on a side note: the use of dimensions in R4..R6 is rather limited. All dimensions will have the same unit, origin, scale factor and limits. Ideally these are defined per dimension.
