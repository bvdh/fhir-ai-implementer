- **Related Artifact(s)**: TestPlan
- **Resolution Description**: scope (TestPlan.scope and TestPlan.testCase.scope) will change to canonical(ActivityDefinition, ActorDefinition, CapabilityStatement, ImplementationGuide, Library, Measure, MessageDefinition, OperationDefinition, PlanDefinition, Questionnaire, Requirements, StructureDefinition, SearchParameter, StructureMap, SubscriptionTopic)|markdown|uri

### 2. Jose Costa-Teixeira - 2024-09-30

The intent of TestPlan.scope is the same as TestScript.scope, hence making it (any). We can constrain it to canonical resources (ActorDefinition (possibly CapabilityStatement?) is a must, as it is what I'd actually start using TestPlan for).

Since Scope is intended to handle traceability, having multiple would be used for establishing relationship, so my current guess would be that multiple references imply a union? I don't know if it is intended to mean "everything" that actor A does - is that relevant? If we think so, we should probably have a separation between scope and "target"
