- **Resolution Description**: We will update the https://build.fhir.org/search#type-mapping section to add 'Range' as an allowed type for the quantity search-type.
While we're at it, we'll fix all of the links to the search types on the left to actually go to search types, not data types.
In the Decimal Values section of the table in 'prefixes', will add a couple of rows showing behavior for explicit ranges.
In the paragraph that starts "The search processor may choose to perform a search based on canonical units", we will append: "Servers that do not search based on canonical units will not be able to search against ranges whose low and high quantities use different units or where the search expression uses different units than are found in low and high."

- **Description**: Group resource can be use to define eligibility for a trial, using ResearchStudy.recruitment.eligibility : Reference(Group | EvidenceVariable)

A Group can represent an age range e.g. 0-21 year olds:
<Group> ...
<characteristic>
... <code value="age-range"/>
<valueRange>
<low>
<value value="0"/>
<unit value="year"/>
</low>
<high>
<value value="21"/>
<unit value="year"/>
</high>
</valueRange>
<exclude value="false"/>
</characteristic>

However it is not possible to search on the valueRange.

There is only a search parameter characteristic-value, which is composite, but only of code and the value as a code or boolean.

It needs a composite that allows range.

I would expect a 3 way composite of code and range.low and range.high.

Additionally, there is the exclude attribute, and it seems that any search on a characteristic would need to take that into account.

So the existing parameters (characteristic-reference, characteristic-value) and the new one would probably need another composite part to add the exclude attribute.

Going even further, it is probably necessary to add characteristic.period to some of these composites but I don't have a use case for that right now.

### 5. Josh Mandel - 2023-03-27

From FHIR-I discussion: searching a cross numeric ranges could use the same pattern as searching for individual numbers: a quantity-type search param where clients can ask for "&q=gt100&q=lt200". Currently FHIR "quantity" search params can't index a whole range; that's something we can consider for R6.

In the meantime, can you propose a specific SearchParameter you'd like to see on Group, and validate it through some testing or experimentation? For example, you might want to use a composite that covers something like:

.characteristic.code$.characteristic.valueRange.low$.characteristic.valueRange.high

— but this gets pretty complex! If you can provide a design that works well for your use case, we'd be happy to include it as a core search param on Group.
