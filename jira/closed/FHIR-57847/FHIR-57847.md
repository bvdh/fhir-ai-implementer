# FHIR-57847: Consent.period search parameter should also cover the actual validity period of the consent as represented in Consent.period

## Metadata

- **Summary**: Consent.period search parameter should also cover the actual validity period of the consent as represented in Consent.period
- **Created**: 2026-07-10
- **Updated**: 2026-09-08
- **Resolved**: 2026-07-10
- **Status**: Applied
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Mohammad Jafari
- **Resolution**: Persuasive
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R5
- **Work Group**: Security
- **Related Artifact(s)**: Consent
- **Resolution Description**: We will change the definition of the search parameter to point to Consent.period.
- **Resolution Vote**: Mohammad Jafari / Kathleen Connor : 8-0-0
- **Vote Date**: 2026-08-31
- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Description**: Currently the search parameter for `period` is only covering the `period` elements inside provisions and not the top-level Consent.period.

This is likely caused by the fact that Consent.period did not exist in the earlier versions and the validity period of the consent was expected to be expressed in the first provision. When this was changed in later versions, we missed updating the search parameter definitions.
