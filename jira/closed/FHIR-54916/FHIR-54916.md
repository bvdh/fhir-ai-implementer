### 4. Emma Jones - 2026-08-17

See this Zulip Chat related to the this Jira

The practical difference between Extensible and Example binding:
- It's true that under Extensible binding, a code outside the ValueSet can still be used — but only when no suitable concept exists in the ValueSet.
- Under Example binding, there's no such condition at all: implementers may use any code, from any system, even when problem-list-item or encounter-diagnosis clearly applies, and still be fully conformant.
There is a major distinction — Extensible gives validators, IGs, and receiving systems a testable expectation that the standard codes will be used when applicable; Example gives none. In practice, that means downstream systems lose the ability to reliably rely on category to distinguish problem-list items from encounter diagnoses — which is precisely the use most EHRs already depend on this element for (problem list segregation, UI logic, quality measure logic, etc.). Loosening to Example doesn't just permit occasional deviation — it removes any expectation of consistency at all.

### 5. Robert Hausam - 2026-07-09

I think that has been some general agreement (across multiple WGs and resources) that the 'category' element and its use should be kept open and flexible at the base FHIR specification level. If and when more specific requirements on 'category' are imposed, that is most likely going to be appropriate at the profile and IG level (e.g., US Core, IPS). The documentation on preferred bindings also states that "Preferred bindings are used when there is consensus at the specification level about the coded values that are the best to be used". I'm not sure if that is actually the case with the [http://terminology.hl7.org/CodeSystem/condition-category|condition-category] code system (at least it's arguable whether or not it is the case). So it may be best to keep this binding as extensible in the base specification and then tighten the binding to recommend (i.e. "preferred") or constrain (i.e. "extensible" or "required") the allowable values further in the more specific profiles as needed.
