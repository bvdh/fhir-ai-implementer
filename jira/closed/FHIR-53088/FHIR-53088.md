# FHIR-53088: Clarify that complex extensions can't be profiled to add new 'local' components

## Metadata

- **Summary**: Clarify that complex extensions can't be profiled to add new 'local' components
- **Created**: 2025-10-08
- **Updated**: 2025-12-14
- **Resolved**: 2025-11-17
- **Status**: Applied
- **Project**: FHIR Specification Feedback
- **Type**: Change Request
- **Reporter**: Lloyd McKenzie
- **Resolution**: Persuasive with Modification
- **Specification**: FHIR Core (FHIR)
- **Raised in Version**: R5
- **Work Group**: FHIR Infrastructure
- **Related Page(s)**: Extensibility
- **Resolution Description**: Change
"Except for child extensions defined within complex extensions, the URL SHALL be an absolute URL."

to

"Except for child extensions slices introduced in a structure definition defining a complex extension whose base is 'http://hl7.org/fhir/StructureDefinition/Extension', the URL SHALL be an absolute URL."
- **Resolution Vote**: Grahame Grieve/Gino Canessa: 11-0-0
- **Vote Date**: 2025-11-17
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Applied for Version**: R6
- **Description**: It's not completely clear in the spec right now that it's prohibited for profiles of a complex extension to define new 'local URL' extension slices. To make this explicit, suggest that we change

"Except for child extensions defined within complex extensions, the URL SHALL be an absolute URL."

to

"Except for child extensions slices introduced in a structure definition defining a new complex extension, the URL SHALL be an absolute URL."
