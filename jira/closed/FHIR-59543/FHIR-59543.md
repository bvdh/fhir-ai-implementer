- **Resolution Description**: We accept the recommendation to use the publication-status value set.
This replaces the status part of the FHIR-57813 resolution ("a new value set that is the combination of PublicationStatus and MedicationStatus") with the outcome of the analysis above.

Medication.status

Binding: required, http://hl7.org/fhir/ValueSet/publication-status (as CanonicalResource).
Short: "draft | active | retired | unknown".
Definition: "The status of this Medication: whether the medication record is in use."
Comment (replaces the current comment): "This status identifies whether the medication record, in a local system, catalogue or published definition, is in use. For example, a pharmacy system may create a record for a compounded product "ABC Hospital Special Cream" with status active; when the product is no longer to be used, or the record was created in error, its status is retired. This status is not intended to specify whether a medication is part of a particular formulary; the medication may be referenced by several formularies or catalogues, each with their own status."
Is modifier: stays true. Modifier reason: "This element changes the interpretation of all descriptive attributes: a retired Medication should not be used for new references."
Entered-in-error convention (build): .status = retired, as for canonical resources (was .status = entered-in-error).
status-codes.xml: the Medication.status row becomes draft, active, retired, unknown (as Group and DeviceDefinition).

Medication Status codes

Remove the core CodeSystem http://hl7.org/fhir/CodeSystem/medication-status and the ValueSet http://hl7.org/fhir/ValueSet/medication-status from the specification (source/medication/codesystem-medication-status.xml, source/medication/valueset-medication-status.xml); they are no longer used. Their OIDs stay registered in oids.ini.
Remove the stale duplicate source/medicationadministration/valueset-medication-status.xml.

Compatibility (R5 → R6)

Breaking change for Medication.status (required binding): R5 inactive → R6 retired; R5 entered-in-error → R6 retired; active unchanged. Record the mapping in the release notes and in the R5/R6 conversion maps.
Add a release note under "Changes since 6.0.0-ballot5" in the Medication introduction.

- **Description**: FHIR-57813 makes Medication optionally a canonical resource (CanonicalResource elements: url, version, name, title, publisher, …). For status, it resolved: "bind to a new value set that is the combination of PublicationStatus and MedicationStatus". The canonical elements are applied in PR 4339; the status binding is not.

Analysis of the "combination":

Medication Status (current)
Definition
In the combined set

active
The medication record is current and is appropriate for reference in new instances.
Same concept as PublicationStatus active ("ready for normal use") – one code only

inactive
The medication record is not current and is not appropriate for reference in new instances.
Same concept as PublicationStatus retired ("withdrawn or superseded and should no longer be used") – retired is kept

entered-in-error
The medication record was created erroneously and is not appropriate for reference in new instances.
Not kept: canonical resources express this with retired (their entered-in-error status is .status = retired)

So the combined value set is exactly PublicationStatus: draft | active | retired | unknown. No Medication-specific status remains, and there is no reason for a separate value set or code system.
