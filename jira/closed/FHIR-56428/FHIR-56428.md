- **Resolution Description**: We prefer to rename notPerformedReason to statusReason to align with the pattern. We will keep an example binding but to an updated ValueSet, containing codes for the reason why dispense has changed status: Use https://build.fhir.org/valueset-medicationdispense-status-reason.html and add more values (and mention in the description) for changes to on-hold, and resume.
Will inquire with FMG and if there are no issues or objections, we will apply this.
- **Resolution Vote**: Hernany Silva Costa Melo / Benjamin Arfa : 6 - 0 - 0
- **Vote Date**: 2026-05-19
- **Change Category**: Correction
- **Change Impact**: Non-compatible
- **Description**: While the main case for notPerformedReason (as a date of change) is when a dispense is not done, there are other statuses that may be covered by this type element - e.g. reason for on-hold, and again reason for resumed (preparation/in-progress). Not having that requires that systems that wish to implement that cannot use the element and have to resort to an extension. To follow the 80% rule, we don't need to add elements for the 20% less common cases, but we don't have to constrain the scope unnecessarily to disallow those cases.
Therefore the element should be renamed "statusReason" as per event pattern, and the description updated accordingly.
