# FHIR-41220: Operations page has link to "simple parameters" but no definition.

- **Work Group**: FHIR Infrastructure

- **Related Artifact(s)**: OperationDefinition
- **Related Page(s)**: operations
- **Related Section(s)**: 3.3.0.6.1 Operation Request
- **Resolution Description**: Will change "Search Type - for simple string parameters, if they are acting as search parameters, what kind of search parameter they are (and what kind of modifiers they have)" to

"Search Type - for parameters with a data type can be expressed on the URL using the search parameter syntax, identifies the [search type](search#type-mapping) to use when passing the parameter in the URL. NOTE: search type modifiers cannot be used when invoking an operation. Explicit separate parameters are required."

Will change "and all other parameters a client intends to submit are simple parameters,"

to

"all other parameters a client intends to submit have associated [search types](search#type-mapping)."
- **Resolution Vote**: Gino Canessa/Bass Toure: 9-0-0
- **Vote Date**: 2025-12-08
- **Change Category**: Clarification
- **Change Impact**: Non-substantive
- **Applied for Version**: R6
- **Description**: Section 3.3.0.6.1 Operation Request, the following sentence is present:

If an operation has exactly one input parameter whose type is a FHIR Resource and all other parameters a client intends to submit are simple parameters, then the client MAY invoke the operation via POST with the input resource as the request body and additional parameters as query parameters.

Note that "simple parameters" is a link, implying that by following that link you would find out what simple parameters are. However, the link just circles back to the execution section. There are no other occurrences of "simple parameters" in that section, or anywhere on the operations page for that matter. Suggest either defining simple parameters somewhere and linking to that definition or removing the link entirely.
