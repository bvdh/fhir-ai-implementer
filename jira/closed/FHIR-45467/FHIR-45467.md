- **Resolution Description**: Will add canonical<ValueSet> as an allowed value for UsageContext.value
Will will add documentation as follows:

If a 'range' is specified, then the context means that the artifact applies for any value of the context that falls within range. If a 'valueset' is specified, then the context means that the artifact applies if a code matches the value set

Will add documentation to UsageContext saying "If multiple usageContexts are provided, there is no specific interpretation of 'and' or 'or'. I.e. if an age context and a gender context are provided, there is no implication that both age and gender must hold.
Will change the definition of usageContext.value from "A value that defines the context..." to "A value or set of possible values that defines the context"
- **Resolution Vote**: Grahame Grieve/Bryn Rhodes: 10-0-0
- **Vote Date**: 2025-12-15
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: I'm trying to profile Observation such that

if Observation.code is from ValueSet Q1, Observation.valueCodeableConcept is from ValueSet A1
if Observation.code is from ValueSet Q2, Observation.valueCodeableConcept is from ValueSet A2
and so on.

I understand that the way to do this is to add additional bindings to Observation.valueCodeableConcept, }}with a required binding to ValueSet A1, a {{UsageContext.code of "Observation.code", and....

And here's the problem: although I can specify a UsageContext.valueCodeableConcept for a particular code, a there doesn't seem to be a way to specify a UsageContext.value[x] of all codes from a ValueSet. Currently the only way to achieve this appears to be to enumerate a separate context for each value, which is both tedious and fragile.

Another common use case I can see for this is a usage context of a set of jurisdictions or languages.

Please add support for sets of context values.
