- **Resolution Description**: Translated titles are handled through the translation extension

Keywords are handled via UseContext or the artifact-topic extension

In general, name-value pairs are things we want to avoid in FHIR as it makes conformance difficult.

1. We will define a extension-pack extension called "alternate-title" 0..* string with a context of CanonicalResource with definition "Alternative human label for the artifact"
2. We will define a new search parameter:
any-title (searching CanonicalResource.title and this extension)

- **Vote Date**: 2026-09-10
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: `Questionnaire.name` represents a computer-friendly name, while `Questionnaire.title` represents a single human-friendly title. However, standardized questionnaires are frequently known by acronyms, short titles and other alternative names that cannot be distinguished using the current elements.

Consider adding a repeatable complex element based on `ResearchStudy.label`, with elements such as `type`, `value` and `language`. This would allow acronyms, alternative titles and translated titles to be represented.
