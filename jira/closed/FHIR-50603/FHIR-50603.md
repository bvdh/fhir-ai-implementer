### 6. Andrea Pitkus - 2025-05-12

Actually, I wouldn't expect the DiagnosticReport.code to use the Obs only or Order only or Both LOINCs. This is not describing an individual order or result such as lab results, vitals, radiology, surveys, etc. Rather, it is a LOINC code for the entire report type which I'd expect to be from the Document type. There may be a few from other areas of LOINC such as a reference lab report.

Having code on both the DiagnosticReport.code and Observation.code is causing confusion for those implementing as to which codes are supposed to be used for each of these. Further guidance is warranted to help implementers use FHIR correctly and not have inclorrect coding on the wrong Resources. Strongly recommend that guidance be added around each of these. It may be as simple as DiagnosticReport.code is expected to have a LOINC code desciribing the type of report from the Document ontology and less commonly other LOINC types for reports. It is not expected to support order only LOINCs or those for individual Observationss. These should be located on Observation.code
