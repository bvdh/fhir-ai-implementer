- **Resolution Description**: We will add jurisdiction to usageContext as proposed. Needed for obligation and other places where usageContext is used other than base resource.

- **Vote Date**: 2023-08-21
- **Change Category**: Enhancement
- **Change Impact**: Compatible, substantive
- **Description**: To support specifying jurisdiction when usageContext is used as part of the definition of an extension, create a `jurisdiction` code and add the Jurisdiction value set (https://hl7.org/fhir/valueset-jurisdiction.html) to the ConformanceUseContext value set (https://hl7.org/fhir/valueset-use-context.html)

The legal jurisdiction or geographic region for the context of use. Note that this context type is equivalent to the jurisdiction element present in canonical resources and is only used when specifying usage context as part of an extension.

Therefore, instead of adding 'jurisdiction' to the UseContext data type, we will instead define a new extension called 'jurisdiction' with the same definition as the existing Canonical.jurisdiction element and with a context that mirrors the set of resources that are currently allowed by the UseContext extension. This will avoid confusion about whether to convey jurisdiction as part of UseContext or as a distinct element and will also make it easier to independently manage conformance expectations for jurisdiction, as we can currently do for canonical resources.
